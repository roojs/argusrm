## Purpose

- 🔷 Phase 1 proof: one Windows desktop enrolled, then manageable.
- 🔷 The agent is installed as admin before this flow.
- 🔷 Argus broadcasts on Avahi for a short time.
- 🔷 Avahi runs only on Argus. The agent, the phone, and a desktop controller only browse.
- 🔷 A controller, or a command-line tool, opens that window.
- 🔷 The controller shows a number.
- 🔷 The agent is hunting. The person types the number on the desktop.
- 🔷 Registration is the RPC certificate flow used by the other projects.
- 🔷 The second socket is fixed in the Argus config.
- 🔷 The registration response sends that socket info to the client.
- 🔷 The record starts pending, or in process.
- 🔷 The agent downloads the osquery installer from Argus on a second socket, then installs it.
- 🔷 That download socket is not the main app socket. A file transfer must not clog registration, commands, or the identity post.
- 🔷 A basic query then fills the record.
- 🔷 Identity to store:
  - Username.
  - Computer name.
  - Type of computer.
  - Speed.
  - An identifier that can be referenced.
  - Some network information.
- 🔷 Server records follow osquery’s data to a large degree.
- ℹ️ Phone steps and the two registration kinds are below.
- ℹ️ OLLMchat: `ollmfilesd/ClientCert.vala`, `libocrpc/Transport/PairPublish.vala`.

---

## Registration window

- 🔷 `⏳` Argus can be told to broadcast availability for a short time.
- 🔷 `⏳` That publish is the only Avahi use. Clients browse.
- 🔷 `⏳` The instruction comes from a controller, or from a command-line tool.
- 🔷 `⏳` A number is shown to the person who opened the window.
- 🔷 `⏳` The agent registers only while that window is open.
- 🔷 `⏳` The registration response includes the download socket from the Argus config.
- ℹ️ OLLMchat shows a six-digit PIN and keeps the window near 60 seconds.
- 💩 Use that length and that number of digits. Confirm before build.

---

## Two kinds of client

- 🔷 `⏳` A managed agent enrolls as a machine.
- 🔷 `⏳` A controller enrolls on the same broadcast and the same certificate call.
- 🔷 `⏳` A controller is stored as a control client.
- 🔷 `⏳` A controller does not install an agent, and does not install osquery as part of enrollment.
- 🔷 `⏳` The first thing a control client can do is open the registration window.
- 🔷 The control client is usually Linux. It can be Windows.
- 🔷 The phone is the control client for this proof.
  - Install the Android client.
  - Tell Argus to broadcast.
  - The phone shows the number.
  - Type it into the desktop.

---

## Windows agent

- 🔷 `⏳` Admin install.
- 🔷 `⏳` After install it browses for the Argus broadcast.
- 🔷 `⏳` It takes the number, then completes certificate registration.
- ℹ️ Snappr’s Windows packaging is the precedent for an admin install and a resident process.

---

## osquery and the record

- 🔷 `⏳` Argus can hand out the Windows osquery installer.
- 🔷 `⏳` After the certificate is stored, the agent downloads that file on the download socket and installs it.
- 🔷 `⏳` The main app socket stays free while that download runs.
- ℹ️ The agent already has the download socket from the registration response.
- ℹ️ The same download socket is what later package installs use. See [1.3](1.3-install-software.md).
- 🔷 `⏳` It runs a basic query and sends the identity fields in Purpose.
- 🔷 `⏳` Argus moves the record from pending or in-process to that full identity.
- 💩 Read those fields from osquery `system_info`, the logged-in user, and the interface addresses. Confirm the tables before build.

---

## Suggested build order

- 💩 `⏳` Argus window first: broadcast, number, certificate issue, machine versus controller, and the osquery file.
- 💩 `⏳` Command-line open, so the server can be tried before the phone exists.
- 🔷 `⏳` Android client: open the window and show the number.
- 🔷 `⏳` Windows agent: hunt, accept the number, install osquery, post identity.
