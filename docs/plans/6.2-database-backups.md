# 6.2 Database backups

**Status:** ⏳ proposed

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**. Proposed Vala follows `docs/coding-standards.md`.

**Parent:** [3.0 Server](3.0-server.md)

---

## Purpose

- 🔷 `⏳` Keep a dated copy of the server database, one per day, by default.
- 🔷 `⏳` The date in the name is year, month, day.
- 🔷 `⏳` Prune old copies. The prune runs on that same daily pass.
- ℹ️ The live file is already saved. This plan adds the dated copies beside it.
- ℹ️ Dated copies and a once-a-day prune already exist for edited files in OLLMchat, not for this database. `ollmfilesd/FileHistory.vala` names a backup with `%Y-%m-%d`. `cleanup_old_backups` runs at most once a day and deletes records older than `files_max_deleted_days` (30).

---

## Current behaviour

- ℹ️ The server opens `SQ.Database` on `/var/lib/argusrm/argus.sqlite` with autosave on (`server/Application.vala`).
- ℹ️ The working copy is in memory. `backupDB()` writes that memory back over `argus.sqlite`.
- ℹ️ Autosave checks every 60 seconds and writes when the memory copy is dirty. Mutations also call `backupDB()`. Shutdown calls `backup_real()`.
- ℹ️ One live file. A bad day overwrites it. Nothing dated is kept, and nothing is pruned.

---

## Daily copy

- 🔷 One copy per calendar day. A second start on the same day does not add another file.
- 🔷 The date is `YYYY-MM-DD`.
- 🔷 This is on by default. A server that stays up past midnight writes the new day without a restart.
- 🔷 The live file stays `argus.sqlite`. The dated file is a separate copy.
- 🔷 Copies stay under the state directory. That directory is mode `0700`.
- 💩 The directory is `backups/` inside the state directory. The file is `argus-YYYY-MM-DD.sqlite`.
- 💩 Write the copy from the in-memory database with the SQLite backup API, the same write `backup_real` uses. Do not copy `argus.sqlite` off disk while a save is in progress.
- 💩 On startup, write today's file when it is missing. The daily check writes it when the date changes.
- 💩 Each dated file is mode `0600`.
- 🚫 Do not change `SQ.Database.backupDB` in libocsqlite. The live overwrite stays as it is.
- 🚫 No setting to turn the copies off.
- 🚫 No hourly copies, and no weekly or monthly set.

---

## Prune

- 🔷 The daily pass deletes old dated copies.
- 💩 Keep 30 days, the same number as `files_max_deleted_days` in OLLMchat. That number was not stated for Argus.
- 🚫 Do not delete `argus.sqlite`.
- 🚫 Do not delete anything outside `backups/`.

---

## Where it runs

- 💩 In `server/Application.vala`, after the database is open. No new class.
- 🚫 No controller page, and no restore command, in this plan.
