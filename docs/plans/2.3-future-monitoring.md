## Slow-changing host state (deferred)

- 🔷 `⏳` Tables in scope:
  - `os_version`
  - `interface_addresses`
  - `system_info`
- 🔷 `⏳` Trigger interval:
  - Run once every 24 hours (`24 * 60 * 60` seconds).
  - These tables rarely change after startup.
- 🔷 `⏳` Local client cache:
  - Keep a local cache of the last sent rows on the agent.
  - On the 24-hour check, query osquery and compare against the cached state.
  - Only send `OSQuery.sync` to the server when the table data has changed.
- 🔷 `⏳` Host environment constraint:
  - Managed Linux agents include LXC guests on SysV init with no systemd or journald.
  - Periodic timers must use GLib timeouts (`GLib.Timeout.add_seconds`), not systemd timers.
- ℹ️ Agent transport uses existing `OSQuery.sync` and row classes (`OsVersion`, `InterfaceAddresses`, `SystemInfo`) in `agent/OSQuery/Execute.vala`.
- ℹ️ Controller cache invalidation will need those table names added when this plan is built ([2026-11-14-package-status-cache-notification.md](../bugs/2026-11-14-package-status-cache-notification.md)).
- 💩 `⏳` Optional later enhancement for `interface_addresses`: add a debounced network trigger (netlink / route or address change) alongside or instead of the 24-hour timer.
- 💩 `⏳` Optional `mounts` daily refresh ([2026-11-16-FIXED-machine-additional-osquery-data.md](../bugs/done/2026-11-16-FIXED-machine-additional-osquery-data.md)) could share the same 24-hour cached sync mechanism later.
- ℹ️ Code proposals are intentionally omitted while this work stays deferred.
