---

## Purpose

- 🔷 The Agents place: the list of registered machines, and how a row is removed.
- 🔷 One button adds a machine. It opens the pairing dialogue that already exists.
- 🔷 This page has no tick column. The grid's own selection is the selection.
- 🔷 Removing a machine is a low-frequency removal. [5.5 Selection](5.5-controller-user-interface.md).
- ℹ️ Saved filters are [5.7](5.7-list-filters.md). This page does not grow that control yet.
- 🚫 This plan does not name widget classes or new tables.
- 🚫 This plan does not delete rows by itself. The leftover controllers come off once the page can select more than one.

---

## Page

- 🔷 The grid fills the page under the page's own bar. There is no lower region.
- 🚫 The window header bar is the title only. Buttons do not go there.
- 🔷 There is no Remove button under the list.
- 🔷 The columns stay: Hostname, Address, User, Kind, Registered, Registered on, Connected, Last connected.
- 🔷 Registered starts hidden. A right-click on a column header shows or hides each column. The last visible column stays.
- 🔷 The list is `Agent.list`. A remove is `Agent.remove`.
- 🔷 Agents has no edit. Double-click does nothing here.

## Selection and remove

- 🔷 Several rows can be selected. The selection is the grid's own.
- 🚫 This page has no tick column.
- 🔷 On a desktop, right-click opens a menu. Remove on that menu asks. A confirmation names the selected machines. Cancel leaves them.
- 🔷 On a tablet, a long press on a row reveals Remove on the right.
- 🔷 A long hold on that button runs a sliding timeout. When it finishes, that row is removed. A tablet has no confirmation dialogue.
- 🔷 `Agent.remove` takes one id. The page loops it, one selected id after another.
- 🔷 While that loop runs, a spinner shows, with Removing. The list reloads when the loop finishes.
- ℹ️ This server has about five or six controller rows that are not live machines. Selecting those and removing them is the first use of this.

Desktop. Removing a machine is rare, so it asks.
