# 5.13 Windows MSI components

**Status:** ✔️ applied. Windows test on DESKTOP-GITPJFF: 1014 snapshot rows, `system_component` 171, 62 `programs` rows still shown, 127 `appx` still shown. Visual Studio Community 2026, the installer, and both Windows SDK entries are in the shown set. `Windows SDK Desktop` pieces are not.

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**. Proposed Vala follows `docs/coding-standards.md`.

---

## Purpose

- 🔷 Show the installed product. Hide the MSI pieces that belong to it.
- 🔷 On this machine the products are Visual Studio Community 2026, Microsoft Visual Studio Installer, and the two Windows Software Development Kit entries.
- 🔷 A piece is hidden when its uninstall key has `SystemComponent=1`. That flag is the installer's own. It is not the install path and not the publisher string.
- 🔷 The rows stay stored. `Programs.list` leaves them out. The next sync does not delete them.
- ✔️ The snapshot records the flag. The list calls omit it.
- ℹ️ Measured on DESKTOP-GITPJFF, 2026-11-24. 185 MSI product codes. 170 have `SystemComponent=1`. 15 do not, so they stay visible.
- ℹ️ Those 15 are osquery, OpenVPN Connect, Net2 Access Control OEM SDK, Autodesk Design Review Browser Add-on, Microsoft Silverlight, two SQL Server CLR packages, Microsoft Update Health Tools, two Visual C++ 2010 redistributables, two Windows updates, Windows PC Health Check, Windows SDK AddOn, and `vs_CoreEditorFonts`.
- ℹ️ The signed MSI names the product. `SystemComponent` only says whether that entry is a piece. Install source is not the check.
- 💩 Appx is still open. This hide does not cover it. See **Appx**.

## MSI components

- 🔷 `snapshot_sql` reads `SystemComponent` on the uninstall key, both the native key and `WOW6432Node`.
- ℹ️ An `EXISTS` on `registry` returned no rows on this machine. A `printf` subquery on `registry.path` returned 171. The snapshot uses that subquery.
- 🔷 The value is `1` or `0`, stored on `programs.system_component`.
- 🔷 Chocolatey, service, and startup rows store `0`.
- 🔷 `Programs.list` adds `system_component != '1'` on every select it already runs.
- ℹ️ Osquery returns the column as text. The property is a string, like the other snapshot columns.
- ℹ️ A row already stored, with the column still empty, stays visible until that agent syncs again.

Edits are **Remove** / **Replace with** / **Add** from the tree. Verify the surrounding lines before applying.

### 1. `shared/OSQuery/Programs.vala` — `snapshot_sql`: record `SystemComponent`

**Why:** the list cannot hide a piece unless the snapshot brought the flag.

**Where:** the `programs` select, after `uninstall_string`. Then the same column on the chocolatey, service, and startup selects, after each `uninstall_string`.

**Depends on:** none.

#### Remove

```vala
					uninstall_string,
					'source_reg=' || install_source
						|| ';uninstall=' || uninstall_string AS extra
				FROM programs
```

#### Replace with

```vala
					uninstall_string,
					CASE
						WHEN (SELECT data FROM registry WHERE path = printf('%s%s%s', 'HKEY_LOCAL_MACHINE\\SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\', identifying_number, '\\SystemComponent')) = '1'
							OR (SELECT data FROM registry WHERE path = printf('%s%s%s', 'HKEY_LOCAL_MACHINE\\SOFTWARE\\WOW6432Node\\Microsoft\\Windows\\CurrentVersion\\Uninstall\\', identifying_number, '\\SystemComponent')) = '1'
						THEN '1'
						ELSE '0'
					END AS system_component,
					'source_reg=' || install_source
						|| ';uninstall=' || uninstall_string AS extra
				FROM programs
```

#### Remove

```vala
					'' AS uninstall_string,
					summary AS extra
				FROM chocolatey_packages
```

#### Replace with

```vala
					'' AS uninstall_string,
					'0' AS system_component,
					summary AS extra
				FROM chocolatey_packages
```

#### Remove

```vala
					'' AS uninstall_string,
					'status=' || status
						|| ';start_type=' || start_type
						|| ';service_type=' || service_type AS extra
				FROM services
```

#### Replace with

```vala
					'' AS uninstall_string,
					'0' AS system_component,
					'status=' || status
						|| ';start_type=' || start_type
						|| ';service_type=' || service_type AS extra
				FROM services
```

#### Remove

```vala
					'' AS uninstall_string,
					'startup_source=' || source
						|| ';status=' || status AS extra
				FROM startup_items
```

#### Replace with

```vala
					'' AS uninstall_string,
					'0' AS system_component,
					'startup_source=' || source
						|| ';status=' || status AS extra
				FROM startup_items
```

### 2. `shared/OSQuery/Programs.vala` — column and property

**Why:** the flag has to land in `programs` and on the row object.

**Where:** `init_db`, after the `signer_serial` alter. The property sits with the other stored strings, after `identifying_number`.

**Depends on:** none.

#### Add

After the `signer_serial` alter in `init_db`.

```vala
			db.exec("ALTER TABLE programs ADD COLUMN system_component TEXT NOT NULL DEFAULT '';");
```

#### Add

The column in `CREATE TABLE`, after `identifying_number`.

```vala
					system_component   TEXT NOT NULL DEFAULT '',
```

#### Add

The property after `identifying_number`.

```vala
		/**
		 * ''1'' when the uninstall key sets SystemComponent.
		 * ''0'' when it does not. Empty on a row synced
		 * before this column existed.
		 */
		public string system_component { get; set; default = ""; }
```

## Appx

- 🔷 After the MSI hide, the Store rows are still in the list.
- ℹ️ They are `programs` rows with `package_family_name` set. The snapshot labels those `source` `appx`. On this machine that is 127 rows. None has a file hash. None has `SystemComponent=1`.
- 💩 No hide rule for them yet. `SystemComponent` does not apply. A name or install-path guess is the kind of check already rejected for the MSI pieces.

## LLM notes

- ℹ️ Parent rows are not MSI component codes. Their uninstall strings call `setup.exe` or `winsdksetup.exe`. The registry join does not mark them `1`.
- ℹ️ Services and the signer ignore set stay in `docs/bugs/2026-11-23-ISSUE-programs-windows-installed-vs-noise.md`.
- 🚫 Do not classify a piece by install source, by the publisher string, or by parsing `msiexec`.
- 🚫 Do not drop `SystemComponent=1` from the snapshot. The list hides them. The rows remain for a later sync.
