## Purpose

- 🔷 Build Argus in `server/`.
- 🔷 It starts up.
- 🔷 It can create a pin and show it.
- 🔷 Then the server half of enrollment, the machine record, and remote command execution.
- ℹ️ The product is [1.0](1.0-overview.md). The agent is [2.0](2.0-agent.md). The call list is [RPC commands](../rpc-commands.md).
- ℹ️ The catalog, install, uninstall, warnings, and the Debian package stay in [1.0](1.0-overview.md) until a later phase.

## Phase 1 — start up

- 🔷 `✔️` `server/` is Argus. Source for this program lives in that directory.
- 🔷 `✔️` Link `libocrpc`. Do not copy the library into this tree.
- 🔷 `✔️` The process starts up. `Initialize.fetch_osquery` runs before the sockets bind.
- 🔷 `✔️` Two sockets.
  - The app socket is the RPC. Registration, commands, identity, and warnings stay here.
  - The download socket is fixed in the Argus config.
- 🔷 `✔️` The registration response sends that download socket to the client. Index 2 of `ClientCert.request_registration`.
- 🔷 `✔️` The download socket only listens for download requests.
  - A download is a standard HTTP GET over TLS, authenticated with the client certificate.
  - The server allows or refuses that certificate.
  - The URL path is a file under the package store, default `/var/lib/argusrm/packages`. A path with `..` is refused.
- 🔷 `✔️` A transfer on the download socket must not clog the app socket.
- 🔷 `✔️` Initialization fetches the latest osquery deb, rpm, and msi into `localstatedir/lib/argusrm/packages/osquery/`, saved as `osquery.deb`, `osquery.rpm`, and `osquery.msi`. The default is `/var/lib/argusrm/packages/osquery/`. A file already there is left in place. The legacy `localstatedir/lib/argusrm/osquery/` directory is moved into the package store on startup. The GitHub body is `Argus.Server.GitHub.Release` in `server/GitHub.vala` (`Json.Serializable`, read only).
- 🚫 `Download.get` is not this fetch.
- ℹ️ `ollmfilesd/Application.vala` is the headless server that opens its listen socket. `ollmfilesd/SslListen.vala` is the TLS listen. This program is not the file daemon.
- 💩 `✔️` The executable is `argus`. Top `meson.build` calls `subdir('server')`.
- 💩 `✔️` The namespace is `Argus.Server`. `server/namespace.vala`, `server/Application.vala`, `server/Initialize.vala`, and `server/GitHub.vala`.
- 💩 `✔️` `sysconfdir/argusrm/socket` and `sysconfdir/argusrm/download` are each one `host:port` line. The default `sysconfdir` is `/etc`, so the files are `/etc/argusrm/socket` and `/etc/argusrm/download`. `--socket` and `--download` override them. With no line, the process listens on `0.0.0.0` and the build ports. The Phase 5 iptables class locks that listen down. `-Dsocket_port` and `-Ddownload_port` are system ports, 1–1023. The defaults are 817 and 818. Runtime data is under `localstatedir/lib/argusrm`; downloadable packages are under its `packages/` directory. The default `localstatedir` is `/var`, so the package store is `/var/lib/argusrm/packages`. `paths.vala.in` receives the directories and the ports from the build.

## Phase 2 — pins and enrollment

- 🔷 `✔️` `controller/` is the command-line client. Executable `argus-controller`.
- 🔷 `✔️` It creates the six-digit pin the way `PairingDialog.open` does, prints that number, and calls `ClientCert.pair` on the Unix socket.
- 💩 `✔️` That printed number is the pin. The server does not create a second one. `ClientCert.pair` stores it on `SslListen.pin`.
- 🔷 `✔️` The Unix socket is `localstatedir/lib/argusrm/argus.sock`. The default is `/var/lib/argusrm/argus.sock`.
- 🔷 `✔️` Avahi publish runs only on Argus, from `ClientCert.pair`, through `OLLMrpc.Transport.PairPublish`. An empty pin stops it. Clients browse.
- 💩 `PairPublish.start` returns false when the port is below 1024. The app port default is 817, so the publish does not go out. Registration by host and port still works while the pin is set.
- ℹ️ The pattern is `libocrpc/Transport/PairPublish.vala`.
- ℹ️ OLLMchat creates the pin in `ollmapp/SettingsDialog/PairingDialog.vala` and stores it with `ollmfilesd/ClientCert.pair`.
- 🔷 `✔️` The server accepts the pin only while that window is open. An empty `SslListen.pin` rejects the call.
- 🔷 `✔️` Sixty seconds after the pin is accepted, `argus-controller` sends an empty pin. That is the `PairingDialog` limit.
- 🔷 `✔️` Registration is `ClientCert.request_registration` in `server/ClientCert.vala`, adapted from `ollmfilesd/ClientCert.vala`. The agent already calls it.
- 🔷 `✔️` The call arguments are the pin, the certificate request, the requester, and the OS family.
  - Windows sends `windows`. Android sends `android`.
  - Debian and Ubuntu send `debian`. Fedora, RHEL, CentOS, and SUSE send `rpm`.
- 🔷 `✔️` The reply is a string array.
  - Index 0 is the client certificate PEM.
  - Index 1 is the CA PEM.
  - Index 2 is the download socket `host:port`.
  - Index 3 is the download URL path. `debian` is `/osquery/osquery.deb`. `rpm` is `/osquery/osquery.rpm`. `windows` is `/osquery/osquery.msi`. `android` is empty.
  - Later entries are listen addresses.
- 🔷 `✔️` A matching pin stores an `agent` row with status 1. The file is `localstatedir/lib/argusrm/argus.sqlite`. `is_controller` is 0 on that insert. See [4.0](4.0-data-types.md).
- 💩 `✔️` The call has no machine-or-controller argument. The local controller is the Unix socket, not a row.
- 🔷 `✔️` Status 0 is only the open window before a row exists. `SslConnection` allows a later call when status is 1 and stores that row's id on the connection.

## Phase 3 — machine record

- 🔷 `✔️` The machine is the `agent` row. Osquery rows point at `agent.id`. Columns are [4.0](4.0-data-types.md).
- 🔷 `✔️` First data is only identity, stored in the osquery tables.
  - Username is `logged_in_users.user`.
  - Computer name is `system_info.computer_name`.
  - Type of computer is `system_info.hardware_model`.
  - Speed is `cpu_info.current_clock_speed`.
  - The identifier is `agent.id`. `system_info.uuid` is the hardware id.
  - Network information is `interface_addresses`.
- 🔷 `✔️` The agent posts that with `OSQuery.sync`. One call per table. The arguments are the registered row name and the array of row objects.
  - Tables: `system_info`, `cpu_info`, `logged_in_users`, `interface_addresses`.
  - An empty array is sent too. Rows missing from the new snapshot are deleted.
- 🔷 `✔️` `SslConnection.agent_id` is the approved `agent.id` for the certificate. `OSQuery.sync` writes the snapshot against that id.
- ℹ️ The row objects are `Argus.Shared.OSQuery`. The property name is the column name. The agent side is [2.0 Phase 3](2.0-agent.md).
- 💩 `✔️` There is no second machine record. The osquery tables are the record.
- 🔷 `⏳` After identity, the agent collects the installed programs and Argus stores them against the machine.
- 💩 `⏳` The programs table and the store are not this phase. See [1.0 Software](1.0-overview.md).

## Phase 4 — remote command

- 🔷 `✔️` The server tells the connected agent to run a command. That tell is a client notification, on that agent's connection.
- 🔷 `✔️` A broadcast notification goes to every connection. A client notification goes to one connection.
- 🚫 Signals and `RPC-Live-Subscribe` are not this.
- 🔷 `✔️` Every notification has a method.
- 🔷 `✔️` On the server the object is `Argus.Server.Command`. The server makes it.
- 🔷 `✔️` On the agent the object is `Argus.Agent.Command`. The two classes do not have to be the same. The server command maps to the agent command.
- 🔷 `✔️` Down the wire the object is `Argus.Command`.
  - The identifier.
  - The command.
  - The environment variables.
  - The current working directory.
- 💩 `✔️` The notification that starts the command is `agent.run`. Its argument is that one object. The agent listener switches on `agent.run`.
- 🔷 `✔️` A later notification can follow up on a running command. The method is `agent.send`, with an id.
- 💩 `✔️` The id is the command `identifier` string. Arguments are `ss`: identifier, then the text. `Notification.id` is an int and is not this id.
- 🔷 `✔️` The agent sends `Command.stdout`. Each call is the next stdout chunk.
- 🔷 `✔️` The agent sends `Command.stderr`. Each call is the next stderr chunk.
- 💩 `✔️` Both are arguments `ss`: identifier, then that chunk. The call does not resend the command.
- 🔷 `✔️` Argus writes that output to a file.
- 🔷 `✔️` Argus then sends a client notification on the controller connection that initialized the run, when that connection is still up.
- 🔷 `✔️` A controller that initialized an install can watch that install.
- 🔷 `✔️` The type name says the controller receives it.
- 💩 `✔️` The controller notification after `Command.stdout` is method `controller.stdout`. Arguments are `ss`: identifier, then that chunk.
- 💩 `✔️` The controller notification after `Command.stderr` is method `controller.stderr`. Arguments are `ss`: identifier, then that chunk.
- 💩 `⏳` How the server learns that the process exited was not named.
- 💩 `✔️` `server/Command.vala` is `Argus.Server.Command`. The bin alias is `Argus.Command`. Properties are `identifier`, `command`, `environment`, and `cwd`, in that order.
- 💩 `✔️` A controller calls `Command.run`. Arguments are `xo`: `agent.id`, then that object. The Unix socket may call it. A TLS connection may call it when that row's `is_controller` is set. The server writes method `agent.run` on the running app-socket connection for that id. The identifier cannot be empty, `.`, `..`, or contain `/`.
- 💩 `✔️` A controller calls `Command.send` the same way. Arguments are `ss`. The server writes method `agent.send` on the agent connection that accepted that `run`.
- 💩 `✔️` `Command.run` stores `localstatedir/log/argusrm/commands/yyyy/mm/dd/` from the day the command starts. The default directory is `/var/log/argusrm`. Stdin, stdout, and stderr append there for the rest of that run. The file is `{agent.id}-{identifier}` with `.stdin`, `.stdout`, or `.stderr`. The call must come from that agent. `Connection.running` is the still-up check.
- ℹ️ The agent side is [2.0 Phase 4](2.0-agent.md). The agent does not write the file and does not send the controller objects.

## Phase 5 — public servers

- 🔷 `⏳` This phase locks down public machines while allowing agent enrollment.
- 🔷 `⏳` The agent is installed on public servers. Those machines are usually Debian Linux.
- 🔷 `⏳` The firewall is iptables. Its default mode allows the app and download sockets only from registered client IP addresses.
- 🔷 `⏳` A successful registration stores the connection's source IP address in the Argus database against that approved client.
- 🔷 `⏳` Starting the 60-second registration window temporarily allows connections to the app socket from every IP address. The PIN is still required to register.
- 🔷 `⏳` Closing or timing out the registration window restores the database-backed allowlist. It includes the source IP of every client registered during that window.
- 🔷 `⏳` The download socket remains limited to registered IP addresses and still requires a registered client certificate.
- 🔷 `⏳` The certificate remains the client identity and authentication. The IP allowlist is an additional network filter, not a replacement for certificate checks.
- 🔷 `⏳` The iptables class manages those rules.
  - On startup it reads the registered IP addresses from the database and installs the default allowlist.
  - It opens the app socket globally when registration starts.
  - It restores the allowlist when registration stops.
- 💩 `⏳` A registered client can change public IP address. How an administrator safely updates that address without reopening registration is still open.
- ℹ️ Also recorded in [1.0 Public servers](1.0-overview.md).

- 🔷 `⏳` Argus tells the agent which installed package to remove.
