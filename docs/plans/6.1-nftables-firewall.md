# 6.1 nftables firewall

**Status:** ⏳ proposed — external network first

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**.
Proposed Vala must follow `docs/coding-standards.md`.

**Parent:** [6.0 Security issues](6.0-security-issues.md)

**Server:** [3.0 Phase 5](3.0-server.md#phase-5--public-servers)

---

## Purpose

- 🔷 `⏳` Add `Argus.Server.Net.NFTables` to manage the Argus firewall policy.
- 🔷 `⏳` Protect an externally routed server port.
- 🔷 `⏳` Allow source IP addresses recorded against registered agents.
- 🔷 `⏳` Reject other access to that protected port.
- 🔷 `⏳` Apply the database-backed allowlist during server startup.
- 🔷 `⏳` Keep the current allowlist in memory.
- 🔷 `⏳` Refresh the active policy by adding and removing only changed addresses.
- 🔷 `⏳` Allow enforcement for a protected port to be turned fully on or off.
- 🔷 `⏳` Support IPv4 and IPv6 addresses.
- 🔷 `⏳` Make the first implementation external-network-only.
- ℹ️ Internal-network policy may be added later.

## Phase 2 — `NFTables` class

- 🔷 `✔️` Add the object-style wrapper as `server/Net/NFTables.vala`.
- 🔷 `✔️` Wrap the VAPI context behind `NFTables`; callers do not send raw nft command text.
- 🔷 `✔️` Keep server network classes under `Argus.Server.Net`:
  - `server/Net/SslListen.vala`.
  - `server/Net/SslConnection.vala`.
  - `server/Net/Download.vala`.
  - `server/Net/NFTables.vala`.
- 🔷 `✔️` Construct one `NFTables` instance for one protected port.
- 🔷 `✔️` Construction creates the libnftables context, Argus table, chains, sets, and the fixed accept and reject rules.
- 🔷 `✔️` The first `apply()` reads existing set members before calculating its differential.
- 🔷 `✔️` Expose one apply operation receiving the complete new IP allowlist as `Gee.ArrayList<GLib.InetAddress>`.
- 🔷 `✔️` Retain the currently applied addresses as `Gee.ArrayList<GLib.InetAddress>`.
- 🔷 `✔️` A later apply calculates additions and removals against that state.
- 🔷 `✔️` Send only those additions and removals to nftables.
- 🔷 `✔️` Replace the retained state only after the nftables transaction succeeds.
- 🔷 `✔️` Use `apply(Gee.ArrayList<GLib.InetAddress> addresses)` as the update API.
- 🔷 `✔️` Expose operations to enable and disable enforcement without destroying the retained allowlist.
- 💩 `✔️` Name those operations `enable()` and `disable()`.
- 🔷 `✔️` Disabling removes the protected port's jump into the allowlist chain, leaving that port unrestricted by the Argus table.
- 🔷 `✔️` Enabling restores that jump after `apply()` has reconciled the fixed rules and retained allowlist.
- 🔷 `✔️` Make repeated enable or disable calls idempotent.
- 🔷 `✔️` Compare addresses as `GLib.InetAddress` values.
- 🔷 `✔️` When a libnftables command fails, log its buffered error output and leave the retained allowlist unchanged.
- ℹ️ Firewall failures are diagnosed from the server log. They are not exposed as a typed application error.
- 💩 `✔️` Use nftables native command text for the small fixed policy.
- 💩 `✔️` Build one command buffer for each apply so libnftables commits the additions and removals as one transaction.

### Argus-owned rules

- 🔷 `✔️` Create only the table and rules owned by Argus.
- 🔷 `✔️` Leave unrelated host firewall tables and rules unchanged.
- 🔷 `✔️` Match the configured port before applying the Argus allowlist.
- 🔷 `✔️` Accept matching IPv4 and IPv6 source addresses.
- 🔷 `✔️` Drop other traffic to the protected external port.
- 🔷 `✔️` Use one `inet` table per protected port, named `argusrm_<port>`, for example `argusrm_817`.
- ℹ️ Unquoted nftables identifiers may contain numbers after an initial alphabetic character. The `argusrm_<port>` shape therefore needs no quoting.
- 💩 `✔️` Use an input base chain with normal filter priority to select traffic for the protected port and jump to an Argus allowlist chain.
- 💩 `✔️` End the allowlist chain with reject or drop, so unmatched sources to that port are denied without affecting other input traffic.
- 💩 `✔️` Use mutable named sets for allowlist addresses rather than adding one nft rule per address.
- ℹ️ nftables sets have one fixed element type. An `inet` table and chain can handle both families, but IPv4 and IPv6 addresses cannot occupy the same typed set.
- 💩 `✔️` Use one `ipv4_addr` set and one `ipv6_addr` set in the same table.
- 💩 `✔️` In the allowlist chain:
  - Accept `ip saddr` members of the IPv4 set.
  - Accept `ip6 saddr` members of the IPv6 set.
  - Reject or drop everything else that reached the chain.
- ℹ️ These two accept rules remain in place. `NFTables.apply()` changes the elements in their named sets, not the rules themselves.
- ℹ️ Named set elements support direct differential add and delete operations. Individual per-address rules would require retaining nft rule handles for deletion.
- 🔷 `✔️` Match TCP only. Argus has no UDP listener.
- 🔷 `✔️` Make construction idempotent after a daemon restart:
  - Apply the same `argusrm_<port>` table, chain, and set names when they already exist.
  - Add missing fixed chain rules without duplicating existing rules.
  - Leave existing set members in place.
- 🔷 `✔️` Make the first `apply()` idempotent after a daemon restart:
  - Read existing set elements into the retained allowlist state.
  - Reconcile allowlist changes without flushing or recreating the table.
- ℹ️ nftables `add table` tolerates an existing table. Rule insertion is not treated the same way, so construction must not blindly append the fixed rules again.

## Phase 4 — record registration source IP

- 🔷 `✔️` Modify `Argus.Server.Agent.request_registration()` in `server/Agent.vala`.
- 🔷 `✔️` Read the peer IP address from the TLS socket that submitted the successful registration.
- 🔷 `✔️` Store that address in `agent.ip` for either an agent or controller.
- 🔷 `✔️` Store the address without its source port.
- 🔷 `✔️` Parse and store canonical IPv4 or IPv6 text.
- 🔷 `✔️` Complete this persistence before the firewall integration reads the agent table.
- ℹ️ `agent.ip` already uses SQLite `TEXT` and `Argus.Shared.Agent.ip` is a Vala `string`.
- ℹ️ MySQL `INET6_ATON()` returns 4 or 16 binary bytes, not an integer capable of representing both address families. IPv6 cannot fit SQLite's 64-bit `INTEGER`.
- 🔷 `✔️` Keep canonical text storage for this implementation. At this scale it avoids adding `BLOB` support to the SQ row mapping and is parsed into `GLib.InetAddress` before firewall use.

## Phase 5 — local addresses and routes

- 🔷 `✔️` Add `Argus.Server.Net.Address` in `server/Net/Address.vala` for one local address.
- 🔷 `✔️` There is no physical-interface type. `Interfaces` is only the collection of local addresses.
- 🔷 `✔️` `Argus.Server.Net.Interfaces` in `server/Net/Interfaces.vala` holds that collection on `addresses`.
- 🔷 `✔️` `Application` constructs one `Interfaces` and keeps it on `interfaces`.
- 🔷 `✔️` Construction reads this machine's addresses with libnl.
- 🔷 `✔️` Each `Address` stores the `GLib.InetAddress` and `is_internal`.
- 🔷 `✔️` Loopback, link-local, private IPv4, and unique-local IPv6 stay internal. Any other address is public (`is_internal` false).
- 🔷 `✔️` `Interfaces.route()` returns the local `Address` the kernel would use as the source for a destination.
- 🔷 `✔️` Remember that choice. A missing route, or a source that is not one of the local addresses, returns null.
- 🔷 `✔️` Use netlink `rtnl_route_lookup` and the route's preferred source for both IPv4 and IPv6.
- ℹ️ The route library on this machine is `libnl-route-3.so.200` from `libnl-3-dev`. There is no `libnl-route-3.0.pc`.
- ℹ️ A connected datagram socket is not used. The route query is netlink.

## Phase 6 — allowlist through the public addresses

- 🔷 `✔️` Put allowlist gathering in `Argus.Server.Agent.allowlist()`.
- 🔷 `✔️` Build the candidate list with `SELECT DISTINCT ip` so agents and controllers sharing a source address produce one allowlist entry.
- 🔷 `✔️` Exclude inactive rows and empty `agent.ip` values in that query.
- 🔷 `✔️` Parse each candidate into `GLib.InetAddress` before adding it to the list.
- 🔷 `✔️` Permit IPv4 and IPv6 in that list.
- 🔷 `✔️` For each candidate, call `Interfaces.route()`.
- 🔷 `✔️` Keep every registered address when `route()` returns a source, including a private one.
- 🔷 `✔️` Drop a candidate when `route()` returns null. This machine cannot reach it.
- 🔷 `✔️` Do not also filter by the candidate's own prefix. The route's source address is the decision.
- ℹ️ Registration already stores the peer address, private or not. The firewall list keeps it when this machine has a route.
- 💩 `✔️` Ignore invalid legacy `agent.ip` values with a warning rather than interpolating them into nft command text.
- 💩 `✔️` Hand `NFTables` only the kept `GLib.InetAddress` values. It does not see routes or `Address.is_internal`.
- 💩 `✔️` Include both agents and controllers because both use the protected TLS service.

## Phase 7 — start the firewall

- 🔷 `✔️` During server startup, construct `NFTables` for the app socket port, `apply()` the Phase 6 allowlist, and `enable()` it.
- 🔷 `✔️` Keep that instance on `Application.firewall` so later refreshes are differential.
- 🔷 `✔️` `NFTables` stays one port per instance. The caller passes the port. Phase 2 already does this.
- 🔷 `✔️` The class does not know whether that port is registration or normal use. Another instance can protect a second port later.
- ℹ️ Adding or configuring a third external port is later work. It is not part of this implementation.
- ℹ️ Applying nftables policy requires root or `CAP_NET_ADMIN`.
- ℹ️ [6.0](6.0-security-issues.md) proposes a separate privileged firewall broker. Moving execution there is later work, not a blocker here.
- 🔷 `✔️` `NFTables` does not query agents, so allowlist selection can stay outside that broker.
- 💩 `✔️` Apply and enable the firewall before the app socket accepts connections.
- 💩 `✔️` Fail server startup when construction, apply, or enable fails. Continuing would leave the external service open.
- 💩 `⏳` When the listener is wildcard-bound, also match the nft rule to the public local destination addresses, not only the port.
- ℹ️ The firewall list is every registered address this machine can route to. A private route counts. The nft rule matches the protected port and does not name a physical interface.

## Phase 8 — refresh

- 🔷 `✔️` After a successful agent or controller registration, run the Phase 6 query again and `apply()` that complete list.
- 🔷 `✔️` Use that same full query after deregistration rather than calculating the database change at that call site.
- ℹ️ The expected agent count is small. `NFTables.apply()` still sends only the differential additions and removals.
- ℹ️ Adding one address during registration and removing it during deregistration would duplicate allowlist handling on those two paths.

---

## Phase 8.5 — registration broadcast

- 🔷 `✔️` When `Agent.offer` opens registration and starts the broadcast, `disable()` the firewall.
- 🔷 `✔️` When that registration completes, `enable()` the firewall again.
- 🔷 `✔️` Completion is the PIN being used, the sixty-second window ending, or the controller connection closing. `offer` already stops the broadcast on those three.
- 🔷 `✔️` After a successful registration, refresh the Phase 6 allowlist before that `enable()`.
- ℹ️ The app port is open to every address while the broadcast runs. The PIN is still required to register.
- ℹ️ This disable and enable can go away when registration has its own port and its own `NFTables` instance.

- 🔷 `⏳` Register a machine and verify its peer address is stored and becomes reachable after refresh.
- 🔷 `⏳` Verify the shared port is unrestricted only while the registration broadcast is open, and enforcement returns when that registration completes.
- 🔷 `✔️` Verify a stored address is kept when this machine has a route to it, private or public.
- 💩 `✔️` Verify malformed stored addresses cannot become nft command input.
- ℹ️ `server/tests/allowlist.vala` is the meson test `allowlist`. It uses a temporary agent table and this host's routes. It does not open a socket or change nftables. It checks an empty table, inactive and blank rows, distinct addresses, malformed text, and that a routed address is kept whether the route is private or public.
- ℹ️ That test does not open a socket. The packet checks above still need nftables and a second source address.

### LXC — approved host on that route

- 🔷 Localhost to the protected port may stay rejected. That is not work to do.
- 🔷 `✔️` Enforcement already covers every interface. `NFTables.enable()` is `tcp dport <port> jump allowlist` with no interface match.
- 🔷 `✔️` Registration already opens that port. `Agent.offer` disables the firewall, then enables it when the PIN is used, the window ends, or the controller connection closes.
- 🔷 `✔️` A registered agent or controller is allowed when this server can reach that machine.
  - A private address and a public address are the same case.
  - It is on the firewall list because it registered, and this server has a route to it.
- 🔷 `⏳` A machine that has not registered is still blocked, including one on the same private network.
- ℹ️ The server does not look for an LXC container. It asks whether it has a route to that machine.
- ℹ️ The private network is not left open. Until a machine registers, the firewall still blocks it.
