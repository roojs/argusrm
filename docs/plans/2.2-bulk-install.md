## Purpose

- 🔷 Put `argusrm-agent` on many Debian machines from the controller, then register them, without logging into each one by hand.
- 🔷 The host book stays in RooTerm. This desktop already has those hosts, and some LXC containers, in the local RooTerm tree.
- 🔷 RooTerm exports a list. The controller accepts that list pasted in.
- 🔷 Two runs, in this order, on each target:
  - Install. Add the repository, update, install the agent. The service stays stopped.
  - Register. The controller opens registration on the server. The same session runs `argus-agent` with that server address and that PIN.
- 🔷 An LXC container is the same two runs, started with `lxc-attach` from its host. There is no second SSH login and no password inside the container.
- 🔷 The two programs stay separate. Argus does not link RooTerm. RooTerm does not learn Argus packages or PINs.
- ℹ️ The join is the pasted list and the keyring RooTerm already fills. Secrets are not copied into Argus.
- ℹ️ Package install leaves the agent stopped until registration. [2.1.5](2.1.5-installation-packaging.md). Registration is [setup.md](../setup.md).
- ℹ️ RooTerm's tree, `lxc-ls` children, and libsecret schemas live in `app.RooTerm`. The export button is a RooTerm change, written up there after this list format is agreed.

---

## What stays in which program

- 🔷 RooTerm keeps the hosts, the users, the container names, and the logins.
- 🔷 Passwords and SSH key passphrases stay in libsecret, under the schemas RooTerm already uses.
  - `org.roojs.rooterm.Connection` for a password, keyed by connection UUID.
  - `org.roojs.rooterm.SshKey` for a key passphrase, keyed by key path.
- 🔷 `~/.config/rooterm/connections.json` stays free of secrets. Argus may read it to match a pasted line to that UUID and key.
- 🔷 The controller owns the loop, the repository commands, and registration.
- 💩 The controller runs OpenSSH. It does not embed RooTerm and it does not drive RooTerm's terminal.
  - A key RooTerm already installed is the login. The passphrase comes from `org.roojs.rooterm.SshKey` for that run.
  - A password login uses `org.roojs.rooterm.Connection` and feeds it the way RooTerm already feeds a password prompt.
- ℹ️ RooTerm today opens a container with `lxc-console -n` after `sudo -i`. That waits for a login inside the container. Bulk install does not use that path.

---

## The pasted list

- 🔷 One target per line. A line is a host and a user, or a host, a user, and a container name.
- 🔷 A username alone is not a target. The controller has to know where to SSH.
- 💩 The line is `user@host`, or `user@host container` when the row is a container.
- 💩 RooTerm writes those lines from the selected rows. A container row uses the parent host and user, plus `lxc_name`.
- 💩 Matching is against `connections.json`: same host, same user, and the same container name when the line has one.
- 🔷 A line that does not match a RooTerm connection is skipped. The loop says which line, and continues.

---

## Install

- 🔷 Install is the first run. It does not register the machine.
- 🔷 On the host, the session becomes root before any package command.
  - Root login is already root.
  - Otherwise the session runs `sudo -i` and uses the stored connection password, the same step RooTerm uses when sudo-after-login is on.
- 🔷 The root shell then adds the roojs APT repository, updates, and installs `argusrm-agent`.
- ℹ️ The steps are the ones in `scripts/ci/enable-roojs-apt.sh`, then `apt-get install -y argusrm-agent`. That script is not copied onto the remote machine. The loop sends the commands.
- ℹ️ Suites that script accepts: Debian 13 (`trixie`), Ubuntu 25.04 (`plucky`), 25.10 (`questing`), 26.04 (`resolute`).
- 🔷 The package does not enable or start the agent. [2.1.5](2.1.5-installation-packaging.md).
- 🔷 A target that already has the package still gets the repository and the update. Install reports that the package is already present and the loop moves on.

---

## Register

- 🔷 Register is the second run. It runs only after install has finished on that same target.
- 🔷 The controller asks the server for a registration number, the same offer the desktop already uses.
- ℹ️ `Agent.offer` returns six digits and the public address. The number lasts sixty seconds, or until one registration succeeds, or until the controller connection drops. `server/Agent.vala`.
- 💩 One fresh offer per target, issued after install, so the sixty seconds cover only `argus-agent`.
- 🔷 The session runs, as root:
  - `argus-agent --server ADDRESS --pin PIN`
- 🔷 The address and the PIN are the ones from that offer. They are not stored in RooTerm.
- 🔷 Success is the server showing that hostname. The loop then takes the next target.
- 🔷 A failed register is named in the run log. The loop continues with the next target.
- ℹ️ The agent enables and starts its service as part of that command. systemd or SysV, including a container that is not running systemd. [setup.md](../setup.md).

---

## LXC

- 🔷 A container line SSHes to the host, becomes root there, then runs `lxc-attach -n NAME`.
- 🔷 Inside the attach, the commands are the same Debian install, then the same `argus-agent --server --pin`.
- 🔷 The container list is the lines pasted in. This run does not call `lxc-ls`.
- ℹ️ RooTerm already fills those child rows from `lxc-ls` on the host. Refresh there first, then export.
- 💩 A host line is the host only. It does not imply every container on that host.

---

## Where it sits

- 🔷 The paste and the two runs are on the controller, in the Agents place.
- ℹ️ That place is [5.6](5.6-agent-page.md). This plan does not change remove, the two add buttons, or the columns.
- 💩 A third action, Bulk, opens the paste and the two runs. Install can be run without Register. Register can be run on a target that already has the package.

## LLM notes

- 🚫 Do not merge the Argus and RooTerm repositories.
- 🚫 Do not link RooTerm into `argus-controller`, and do not add a RooTerm D-Bus method for this.
- 🚫 Do not put passwords, passphrases, or PINs in the paste, in `connections.json`, or in Argus config.
- 🚫 Do not hold one PIN open for the whole batch.
- 🚫 Do not enable or start the agent from the install run.
- 🚫 Do not use `lxc-console` for the bulk run.
- 🚫 Fedora and the RPM repository are not this plan.
- 🚫 Do not write the RooTerm export until the line format above is agreed.
