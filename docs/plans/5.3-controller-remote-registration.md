## Purpose

- 🔷 Register this controller user with a remote server.
- 🔷 ⏳ Attribute later commands to that certificate.
- 🔷 ⏳ With no desktop, say that a local login has to be run as root.
- 🔷 ⏳ Switching the saved server after the main window is open waits. It is later UI, and it is not critical.
- 🔷 ⏳ Live TLS activation waits until two machines can reach each other through a VPN or the firewall.
- ℹ️ Local certificate issue, the keyring, and `connections.json` are [5.2](done/5.2-DONE-controller-user-registration.md).
- ℹ️ [7.0](7.0-tasks.md) uses this identity for who created and approved a task.

## Phase 1 — remote pairing

- 🔷 ⏳ If no local server is running, tell the user to enable registration on the remote server.
  - That sentence is not shown.
  - Browse text is ''Management server found. Enter the six-digit PIN.''
- 🔷 ✔️ Browse for the server, ask for its registration number, and request a controller certificate.
  - ''Connect a remote machine'' opens `Argus.Shared.RegisterWindow`.
  - The empty-list page also offers ''Log in to local machine''.
  - 🚫 `argus.sock` does not choose between those buttons. The user picks.
- 🔷 ✔️ The remote pairing request includes the controller user's `username` and the controller machine's `hostname`.
  - They are separate registration fields.
  - `is_controller` is set.
- 🔷 ✔️ Store the result through the [5.2](done/5.2-DONE-controller-user-registration.md) password-storage and connection path.
  - `Bootstrap.finish_registration` writes the keyring item and `connections.json`.
- ℹ️ The wire flag is in the tree. Desktop `Argus.Shared.RegisterWindow` is the enroll path.
- 🚫 Do not add the [5.1](done/5.1-DONE-controller-registration.md) command-line `--register` flow. The window replaced it.

---

## Phase 2 — authenticated use and audit identity

- 🔷 ⏳ Make commands attributable to the authenticated user certificate.
- 💩 ⏳ After registration, use TLS with the active connection even when the server is on the same machine.
  - ✔️ The desktop main window already hellos over TLS with the stored certificate.
  - ⏳ `--pin`, `--agents`, and `--command` still hello on the Unix socket.
  - The server maps the certificate fingerprint to the controller `agent.id`.
  - The Unix socket remains the bootstrap and privileged maintenance path.
- 💩 This supersedes the [5.1 Phase 3](done/5.1-DONE-controller-registration.md) suggestion to prefer the Unix socket whenever it exists.
  - A normal Unix request is controller id `0`.
  - It cannot identify which desktop user requested a command.
- 💩 A controller deliberately run as root on the Unix socket is audited as local system control, id `0`.
- 💩 ⏳ Retain the caller controller `agent.id` with each command identifier and target agent id.
- 💩 Store immutable ids rather than only copied username text so later display changes do not rewrite history.
- 💩 The persistent audit row belongs with the command/task schema.
  - Thin `Command.run` needs controller id, target id, identifier, and request time.
  - A task needs creator and approver controller ids in [7.0](7.0-tasks.md).
- ℹ️ Registration provides the authenticated identity but does not itself add the command or task audit columns.

## Phase 3 — no desktop local login

- 🔷 ⏳ Missing: with no desktop, `argus-controller` and no arguments prints usage and exits. It does not say that a local login has to be run as root.
  - Do: print that one fact, and name `argus-controller --give-me-a-certificate USERNAME`.
- ℹ️ Moved from [5.2](done/5.2-DONE-controller-user-registration.md). Small. It does not block remote pairing.

## Phase 4 — switch the saved server

- 🔷 ⏳ Missing: after the main window is open, there is no way to pick a different saved server.
  - Do: add that switch on the main window. Startup already asks when more than one saved server answers.
- ℹ️ Later UI. Not critical. The window picture is [5.5](5.5-controller-user-interface.md).
- ℹ️ Moved from [5.2](done/5.2-DONE-controller-user-registration.md).

---

## Phase 5 — activation across machines

- 🔷 ⏳ Missing: no live run has confirmed that a new controller certificate becomes active over TLS.
  - Do: on two machines that can reach each other, register, then connect. The pending controller row becomes active on TLS `RPC-Daemon.hello`. The returned CA certificate is what validates that server.
- ℹ️ This waits on a VPN or the firewall. Remote activation cannot be tested before that path exists.
- ℹ️ Moved from [5.2](done/5.2-DONE-controller-user-registration.md).

## LLM notes

- 🚫 Do not claim per-user audit while normal local commands still use the anonymous Unix controller id `0`.
- 🚫 Do not write a controller private key under `Argus.AGENT_DATA_DIR`, the user data directory, or `~/.config/argusrm/`.
- 🚫 Do not infer `is_controller` from the OS family.
