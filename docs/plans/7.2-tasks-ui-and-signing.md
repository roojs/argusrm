# 7.2 Tasks UI, package update actions, and signed-task modelling

**Status:** ⏳ proposed — phased design awaiting review before writing verbatim code proposals

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**. Proposed Vala follows `docs/coding-standards.md`.

**Parent:** [7.0-tasks.md](7.0-tasks.md), [7.1-tasks-implementation.md](7.1-tasks-implementation.md), [6.0-security-issues.md](6.0-security-issues.md)

**Bug log:** [2026-11-13-machines-package-update.md](../bugs/2026-11-13-machines-package-update.md)

---

## Purpose

- 🔷 Enable multi-machine **Update** and **Upgrade** from the Machines tab (`controller/tab/Asset/SystemInfo.vala`) using two internal hardcoded commands for now (optionally swappable to library scripts later).
- 🔷 Build the **Tasks** tab (`controller/Window.vala`) to show queued, running, and completed tasks and inspect stdin/stdout/stderr logs in a terminal-style viewer.
- 🔷 Incorporate signed-task and audit fields into the `task` / `task_target` data model so controller-created tasks are ready for task signing (`docs/plans/6.0-security-issues.md`).
- 🔷 Execute the work in four ordered phases, with each phase owning its full specification.

---

## Phases

- 🔷 ✔️ **Phase 1 — Task data modelling:** `task` / `task_target` columns for controller attribution, signed tasks, log lookup, and wire/display fields, plus `SystemInfo.package_manager()` and the two hardcoded command strings (`APT` / `DNF`).
- 🔷 ✔️ **Phase 2 — Controller UI:** Machines row right-click menu (**Update** / **Upgrade**) and the **Tasks** tab with its copyable terminal log viewer (`Tab.Tasks`, `Filters.Tasks`, `task_targets.csv`, `.tool-output`).
- 🔷 `⏳` **Phase 3 — Server handler & task runner:** implement controller task creation, all-tasks/targets listing, log retrieval, signing validation hook, and runner/agent reliability fixes.
- 🔷 `⏳` **Phase 4 — Connect UI & handlers:** wire Machines **Update** / **Upgrade** and the **Tasks** tab + live/saved terminal log streaming to the Phase 3 handlers.

---

## Phase 1 — Task data modelling ✔️

**Scope:** `shared/SQT/Task.vala`, `shared/SQT/TaskTarget.vala`, `shared/OSQuery/SystemInfo.vala`, `docs/plans/7.0-tasks.md`.

### Already in the tree

- ✔️ `Argus.Shared.SQT.init_db(db)` (`shared/SQT/namespace.vala`) already creates `task` and `task_target` at server startup (`server/Application.vala`).
- ✔️ `task` (`shared/SQT/Task.vala`) previously had:
  - `id`, `name`, `is_script`, `command`, `script_id`, `run_as`, `is_template`, `is_draft`, `scheduled`, `completed` (plus `added_dt`, `updated_dt`, `deleted_dt`).
- ✔️ `task_target` (`shared/SQT/TaskTarget.vala`) previously had:
  - `id`, `task_id`, `agent_id`, `scheduled`, `started`, `ended`, `success`, `is_cancelled`, `is_watched`, `timeout`, `identifier` (plus `added_dt`, `updated_dt`, `deleted_dt`).

### Specification

#### 1.1 Controller audit & signed-task fields on `task` ✔️

- 🔷 Task creation happens on the controller and is sent to the server, so `task` records who created/approved it and carries the signing payload (`docs/plans/6.0-security-issues.md`, `docs/plans/5.3-controller-remote-registration.md`).
- ✔️ Added controller attribution columns to `task` (`CREATE TABLE` and `ALTER TABLE`):
  - `created_by` (`INTEGER`, controller `agent.id`, `0` for Unix socket).
  - `approved_by` (`INTEGER`, controller `agent.id`, `0` for Unix socket).
- ✔️ Added signed-task envelope columns to `task` (`CREATE TABLE` and `ALTER TABLE`):
  - `payload_hash` (`TEXT`, canonical SHA-256 digest covering `command`, `is_script`, `run_as`, `scheduled`, and target `agent_id` list).
  - `controller_sig` (`TEXT`, controller signature over `payload_hash` once controller live-mode signing lands; empty while unsigned/local-test mode is permitted).
  - `server_sig` (`TEXT`, server execution grant signature attached at approval/dispatch).
  - `expires_at` (`INT64`, unix timestamp expiry for signed grants; `0` when unset).
- ℹ️ In Phase 3 (`Task.create` / `Task.update`), `created_by` and `approved_by` will be server-assigned.

#### 1.2 Log location & target display model on `task_target` ✔️

- ✔️ Added `log_dir` (`TEXT`, command log directory written by `Command.dispatch`) onto `task_target` (`CREATE TABLE` and `ALTER TABLE`).
- ✔️ Added non-DB joined/display properties on `TaskTarget` following the `{column_name}_{joined_table_column_name}` join prefix convention (`task_id_name`, `task_id_command`, `task_id_is_draft`, `task_id_scheduled`, `agent_id_hostname`, plus `display_task`, `display_state`, `display_started`, `display_duration`, `display_exit`, `dimmed` with `bin_write_prop` omitting `display-*` and `dimmed` on the wire).

#### 1.3 Two hardcoded package commands (`PackageManager` seam) ✔️

- 🔷 Support two hardcoded package commands without requiring `script` / `script_agent` rows (`script_id = 0`), swappable to library scripts later; no extra enum is needed — they are just command strings switched on `Argus.Shared.OSQuery.PackageManager`:
  - **Update** (refresh package metadata / cache):
    - `APT` (`debian`, `ubuntu`, `elxr`): `DEBIAN_FRONTEND=noninteractive apt-get update`
    - `DNF` (`rhel`, `fedora`, `centos`): `dnf -y makecache --refresh`
  - **Upgrade** (install available package upgrades):
    - `APT`: `DEBIAN_FRONTEND=noninteractive apt-get update && DEBIAN_FRONTEND=noninteractive apt-get -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold -y upgrade`
    - `DNF`: `dnf -y upgrade`
  - 🔷 `WIN` / `UNKNOWN`: Windows has no package updater; do not offer Update or Upgrade when only unsupported machines are selected.
- ✔️ Added `SystemInfo.package_manager()` delegating directly to `OsVersion.package_manager()` (`Argus.Shared.OSQuery.PackageManager`) without duplicating platform rules.

## Phase 2 — Controller UI ✔️

**Scope:** `controller/tab/Base.vala`, `controller/tab/Asset/SystemInfo.vala`, `controller/filter/Tasks.vala`, `controller/tab/Tasks.vala`, `controller/Window.vala`, `controller/resources/columns/task_targets.csv`, `controller/resources/argusrm.gresource.xml`, `controller/resources/style.css`, `controller/meson.build`, `docs/meson.build`.

**Depends on:** Phase 1 types (`TaskTarget` display properties, `SystemInfo.package_manager()`).

### Implemented

- ✔️ `controller/tab/Base.vala`:
  - `column_factory` tags data-row cells (`argus-grid-row`) and applies/clears `.dim-label` when a row's `dimmed` property is true (scheduled/unstarted tasks greyed out).
  - `column_menu` skips/denies secondary clicks on data rows (`argus-grid-row`) so row context menus receive them while header/empty-area right-clicks keep opening the column menu.
- ✔️ `controller/tab/Asset/SystemInfo.vala`:
  - Wrapped the paned grid/detail layout in `Adw.ToastOverlay`.
  - Added secondary-click `Gtk.PopoverMenu` (`row.update` / `row.upgrade`) that preserves multi-selection on selected rows, selects the clicked row otherwise, and suppresses the menu when only Windows/unknown machines are selected.
  - Action handlers (`row.update` / `row.upgrade`) are left unwired until Phase 4.
- ✔️ `controller/filter/Tasks.vala` & `controller/tab/Tasks.vala`:
  - Mounted `Tab.Tasks` in `controller/Window.vala` for `"tasks"`.
  - Filter bar: `Gtk.SearchEntry` (matching visible text columns), State `Gtk.DropDown` defaulting to **Active**, Date range `Gtk.MenuButton` (`Any`, `Today`, `Last 7 days`, `Last 30 days`, or From–To `Gtk.Calendar`), refresh button, and spinner.
  - Vertical `Gtk.Paned` with flat `task_targets` `Gtk.ColumnView` above and copyable `Gtk.TextView` terminal log viewer below (matching `OLLMchat` `RenderToolOutput` `.tool-output` CSS: `#000000` / `#ffffff`, `"Droid Sans Mono" 8pt`, no line numbers, stderr `#ff7b72` and stdin `#79c0ff` tags, copy and close buttons).
- ✔️ `controller/resources/columns/task_targets.csv`:
  - Columns: `Machine` (`ON`), `Task` (`ON`, `display-task` first line), `Task name` (`off`), `Command` (`off`), `State` (`ON`), `Start` (`ON`, `display-started` time today / date+time earlier / empty when unstarted), `Duration` (`ON`, `display-duration` `Ns` / `M.SSm` / `H:MMh`), `Exit` (`ON`, `display-exit` empty until ended), plus scheduled/flags/IDs/log-dir (`off`).

### Notes

- ℹ️ `controller/tab/Tasks.vala` currently builds an empty `GLib.ListStore` of `TaskTarget` rows; Phase 3 adds `Task.all_targets` + `Task.logs` on the server and Phase 4 replaces the local placeholder store and connects `row.update` / `row.upgrade`.

## Phase 3 — Server handler & task runner

**Scope:** `server/SQT/Task.vala`, `server/SQT/Scheduler.vala`, `server/Command.vala`, `agent/linux/Command.vala`, `agent/linux/PackageMonitor.vala`, `docs/rpc-commands.md`.

**Depends on:** Phase 1 data model.

### Already in the tree

- ✔️ `Task.create`, `Task.update`, `Task.list`, `Task.target`, `Task.watch`, `Task.approve`, `Task.duplicate`, `Task.targets` are registered in `server/SQT/Task.vala`.
- ✔️ `Task.run` already dispatches ready targets concurrently across connected agents and reschedules busy/offline targets `+60` seconds per machine.

### Specification

#### 3.1 Controller task creation handler (`Task.create` / `Task.submit`)

- 🔷 Controller creates the task on the server and schedules/approves it for the selected agents.
- 💩 Option A (new single RPC `Task.submit` `ovbb` or `oai...`): creates the `Task`, validates & inserts `TaskTarget` rows for `agent_ids`, optionally sets `watch` on those targets for the caller connection, approves `is_draft = false`, and triggers `scheduler.reschedule()` atomically.
- 💩 Option B (existing `Task.create` -> `Task.target` -> `Task.approve`): keep the 3-step chain, and fix `Task.approve` so `scheduled <= 0` (immediate) sets `scheduled = now` instead of failing `"task schedule has passed"`.
- 🔷 Record `created_by` and `approved_by` from `Argus.Shared.Agent.user(request).id`.
- 💩 Signing verification hook: when `controller_sig` is present (or once `6.0-security-issues.md` key enrollment is active), verify `controller_sig` against `payload_hash` before setting `is_draft = false`.

#### 3.2 All-tasks / targets & log retrieval handlers (`Task.all_targets`, `Task.logs`)

- 🔷 **"All tasks" handler** (`Task.all_targets`, no args):
  - Returns `Gee.ArrayList<Argus.Shared.SQT.TaskTarget>` (or `TaskTargetView`) joined with `task` (`name`, `command`, `is_draft`, `scheduled`) and `agent` (`hostname`, `requester`) ordered newest-first (`ORDER BY task_target.id DESC`).
  - Gives the Tasks tab queued, running, and completed machine runs in one RPC.
- 🔷 **Log reader handler** (`Task.logs`, `i` `target_id`):
  - Looks up `task_target` by `id`.
  - If `identifier < 1` (never started yet), returns empty stdout/stderr/stdin.
  - Otherwise reads `{agent_id}-{identifier}.stdin`, `.stdout`, and `.stderr` from the stored `log_dir` (with UTC/local fallback if `log_dir` is empty on older rows).
  - 💩 Returns a string array `as` (`[stdout, stderr, stdin]`) or a small log object so the terminal can render streams distinctly.

#### 3.3 Task runner & agent reliability fixes

- 💩 **`server/SQT/Task.vala` (`Task.run` / `Task.finish`):**
  - Store `task_target.log_dir` when `Command.dispatch` writes the command files.
  - Call `this.app.scheduler.reschedule()` at the end of `Task.finish` so any second task queued behind a busy machine starts immediately when the first task ends instead of waiting up to 60 seconds.
  - Broadcast `event.task` (`action = "started"` / `"ended"` / `"queued"`) so open controller Tasks tabs refresh without manual polling.
- 💩 **`agent/linux/Command.vala`:**
  - If `launcher.spawnv` throws, still report `Command.ended` with exit code `127` (and `Command.stderr` with `e.message`) so `task_target` does not stay `started > 0, ended = 0` forever and block future tasks on that machine.
  - Guard `Command.ended` with `Command.send_lock` (and flush/wait for stdout/stderr channels before sending `Command.ended`) so output chunks never arrive after `ended`.
- 💩 **`agent/linux/PackageMonitor.vala`:**
  - Also call `this.send_pending()` after `apt()` / `rpm()` rescans so `package_updates` (`S/W status` / `update_since`) reflects completed upgrades immediately rather than waiting for the 12-hour timer.
- 🔷 Update `docs/rpc-commands.md` in the same change for any new/modified RPC methods and notifications.

### Open questions (Phase 3)

- ⏳ 🔷 Confirm Option A (`Task.submit` single atomic RPC) vs Option B (existing `Task.create` -> `Task.target` -> `Task.approve` with immediate `scheduled` fix).
- ⏳ 🔷 Confirm whether `Task.logs` returns `[stdout, stderr, stdin]` (`as`) or merged chronological log lines.

## Phase 4 — Connect UI & handlers

**Scope:** `controller/store/TaskTargets.vala`, `controller/tab/Asset/SystemInfo.vala`, `controller/tab/Tasks.vala`, `controller/meson.build`, `docs/meson.build`.

**Depends on:** Phase 2 (UI) and Phase 3 (handlers).

### Specification

- 💩 Add `Argus.Controller.Store.TaskTargets` (`GLib.ListModel` over `Argus.Shared.SQT.TaskTarget`, matching `Store.SystemInfo` / `Store.Repository`):
  - `load()` calls `Task.all_targets` and updates `items`.
  - `fetch_logs(int target_id)` calls `Task.logs` and emits the loaded streams.
  - `queue_package_action(...)` groups selected `SystemInfo` rows by `PackageManager`, builds the `Task` payload (with `payload_hash` and signing hook), calls Phase 3 create/submit RPC, and emits queued/failed signals.
  - Connects `app.rpc.notification`:
    - On `event.task`, reloads `Store.TaskTargets`.
    - On `controller.stdout`, `controller.stderr`, `controller.ended`, filters by the currently viewed target's `identifier` and appends live chunks to the terminal `Gtk.TextBuffer` (or marks ended).
- 🔷 Wire `controller/tab/Asset/SystemInfo.vala` right-click `row.update` and `row.upgrade` actions (`update_action.activate` / `upgrade_action.activate`):
  - Collect selected `Argus.Shared.OSQuery.SystemInfo` rows via `selection.is_selected(i)`, group updatable machines by `package_manager()` (`APT` / `DNF`), build the task payload, and submit via `Store.TaskTargets`.
  - 🔷 Show an `Adw.Toast` on the `Adw.ToastOverlay` confirming how many machines were queued (no confirmation dialog; 💩 optional `"View Tasks"` action).
- 🔷 Wire `controller/tab/Tasks.vala` row selection to:
  - Load historical/current output via `Task.logs(target.id)`.
  - If the selected target is queued or running (`ended == 0 && !is_cancelled`), call `Task.watch(target.id)` so subsequent `controller.stdout` / `controller.stderr` / `controller.ended` stream live into the terminal `Gtk.TextView`.
  - Reload the list on `map` and on `event.task`.

### Open questions (Phase 4)

- ⏳ 🔷 Confirm whether clicking **Update** / **Upgrade** stays on Machines with an `Adw.Toast` (`"View Tasks"` button) or switches directly to the **Tasks** tab.
