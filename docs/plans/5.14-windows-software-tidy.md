## Purpose

- 🔷 The tail of the tidy-up is the machine Windows programs list, read from the spreadsheet.
- 🔷 That spreadsheet has to carry the file hash, the signing result, and the certificate, so the rows can be judged from the file.
- ✔️ The save icon writes those columns. The one-machine `Programs.list` reply fills them.
- 🔷 Appx rows already have an install location. That set is what the spreadsheet is for.
- 🔷 ⏳ Further hides wait until that spreadsheet has been looked at.
- ℹ️ `docs/plans/5.13-windows-msi-components.md` hid MSI `SystemComponent` rows.
- ℹ️ Startup rows stay stored and are left out of the list. A service whose certificate hash is one of the eight Windows hashes in `Programs.list` is left out. An Appx package posted as `NoExecutable` is left out.
- ✔️ 🔷 Five certificates are left out for every source. Appx signed by one of them is ignored.

- ✔️ 🔷 An Appx row with an install location counts as uninstallable. `silent_command` runs `Remove-AppxPackage -AllUsers` for the last folder of that location.
- ✔️ 🔷 The Software page, not the machine page, stores a category. Select rows, right-click, Categorize: System, Installed, Unknown, or Bad. The key for now is the source, a newline, and the name. That is `program_class.ref`. `ProgramClass` owns that table. `program_class.rating` is a `ProgramClass.Rating` number: 1 system, 2 installed, 3 unknown, 4 bad. The flag column reads it. A program or Store package shows a display. A service shows a wireless mark.
- ℹ️ Agent `0.1.47` is the build that posts the hash and the certificate. The desktop list is the server query. The spreadsheet is the controller.
