## Purpose

- 🔷 Review only the column names and SQLite data types used for registration
  and the current osquery data before the server schema is implemented.
- 🔷 The osquery tables are `system_info`, `cpu_info`, `logged_in_users`, and
  `interface_addresses`.
- 🔷 Replace the `client_cert` table with `agent`.
- 🔷 Each osquery row points to `agent`.
- 🔷 Shared osquery rows implement `AgentInfo`, which exposes `agent_id`.
- 🔷 An agent with `is_controller` set can act as a controller.
- ℹ️ The osquery columns match the row objects in `shared/OSQuery/`.
- 🔷 Each osquery row uses `agent_id`, not `client_cert_id` or `owner`.

## Agent registration

`agent` identifies the registered agent and its client certificate.

```
id                    INTEGER
fingerprint           TEXT
status                INTEGER
ip                    TEXT
created               INTEGER
requester             TEXT
is_controller         INTEGER
```

## System information

`system_info` contains the machine and hardware identity returned by osquery.

```
id                    INTEGER
agent_id              INTEGER
hostname              TEXT
uuid                  TEXT
cpu_type              TEXT
cpu_subtype           TEXT

cpu_physical_cores    INTEGER
cpu_logical_cores     INTEGER
cpu_microcode         TEXT
physical_memory       INTEGER
hardware_vendor       TEXT
hardware_model        TEXT
hardware_version      TEXT
hardware_serial       TEXT
board_vendor          TEXT
board_model           TEXT
board_version         TEXT
board_serial          TEXT
computer_name         TEXT
local_hostname        TEXT
```

## CPU information

`cpu_info` contains one row for each processor returned by osquery.

```
id                    INTEGER
agent_id              INTEGER
device_id             TEXT
model                 TEXT
manufacturer          TEXT
processor_type        TEXT
cpu_status            INTEGER
number_of_cores       INTEGER
logical_processors    INTEGER
address_width         INTEGER
current_clock_speed   INTEGER
max_clock_speed       INTEGER
socket_designation    TEXT
```

## Logged-in users

`logged_in_users` contains the sessions reported by osquery.

```
id                    INTEGER
agent_id              INTEGER
type                  TEXT
user                  TEXT
tty                   TEXT
host                  TEXT
time                  INTEGER
pid                   INTEGER
```

## Interface addresses

`interface_addresses` contains the addresses assigned to network interfaces.

```
id                    INTEGER
agent_id              INTEGER
interface             TEXT
address               TEXT
mask                  TEXT
broadcast             TEXT
point_to_point        TEXT
type                  TEXT
```

ℹ️ `type` remains the database column name. The Vala row classes use `ctype`
only because `type` cannot be a Vala property name.

## SQLite compatibility

- 🔷 The shared osquery row objects must remain usable by both the server and
  clients without making clients depend on SQLite.
- 🔷 Each shared osquery class owns its `init_db()` schema.
- 🔷 Client builds compile those classes against the no-op SQLite compatibility
  layer; the server compiles the same classes against SQLite and `libocsqlite`.
