## Purpose

- 🔷 Review only the column names and SQLite data types used for registration
  and the current osquery data before the server schema is implemented.
- 🔷 The osquery tables are `system_info`, `cpu_info`, `logged_in_users`,
  `interface_addresses`, `os_version`, `deb_packages`, `rpm_packages`, and
  `programs`.
- 🔷 Replace the `client_cert` table with `agent`.
- 🔷 Each osquery row points to `agent`.
- 🔷 Shared osquery rows implement `AgentInfo`, which exposes `agent_id`.
- 🔷 An agent with `is_controller` set can act as a controller.
- ℹ️ The osquery columns match the row objects in `shared/OSQuery/`.
- 🔷 Each osquery row uses `agent_id`, not `client_cert_id` or `owner`.

## Standard columns

Every table has these three. The task tables in [7.0](7.0-tasks.md) too. Sync behavior is [5.9.1](5.9.1-assets-software-data.md).

- 🔷 `added_dt`, `updated_dt`, and `deleted_dt`.
- 🔷 The `_dt` suffix marks a datetime. Each value is a unix time, `INTEGER`. `0` means that has not happened.
- 🔷 They are not osquery columns.
- 🔷 ✔️ Stored. [5.9.1](5.9.1-assets-software-data.md) phase 1.

## Operating system

`os_version` is the operating system on the agent. Assets shows the name and version on the machine list.

- 💩 `os_updated`, `os_status`, and `reboot_required` are not osquery columns. [5.11](5.11-os-update.md) fills them. `os_status` is whether the OS version is current. The server writes it once a week. `reboot_required` is a Windows restart waiting.
- 💩 `package_updated` and `package_status` are not osquery columns. [5.10](5.10-data-enrichment.md) fills them. `package_status` is whether installed packages have an update waiting. The agent writes it twice a day, and only when that changed. Confirm the names before building.

```
id                    INTEGER
agent_id              INTEGER
name                  TEXT
version               TEXT
major                 INTEGER
minor                 INTEGER
patch                 INTEGER
build                 TEXT
platform              TEXT
platform_like         TEXT
codename              TEXT
arch                  TEXT
os_updated            INTEGER
os_status             INTEGER
package_updated       INTEGER
package_status        INTEGER
reboot_required       INTEGER
added_dt              INTEGER
updated_dt            INTEGER
deleted_dt            INTEGER
```

## SQLite compatibility

- 🔷 The shared osquery row objects must remain usable by both the server and
  clients without making clients depend on SQLite.
- 🔷 Each shared osquery class owns its `init_db()` schema.
- 🔷 Client builds compile those classes against the no-op SQLite compatibility
  layer; the server compiles the same classes against SQLite and `libocsqlite`.
