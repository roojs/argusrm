## Purpose

- 🔷 Put the server on one live machine, then update Debian from the controller.
- 🔷 The path is: set up the server, open registration there, register this desktop as a controller by IP address, register an agent, log in, list the agents, then update from Assets.
- 🔷 After the agent list, the page is Assets.
  - The top of that page is the Adwaita switcher that tabs one page.
  - The tabs are Machines and Software.
  - Machines are real machines and virtual machines.
  - An operating system is a type of software, so Debian is on Software.
- 🔷 On Software, filter to operating system and to needs updating. That list is the Debian rows that are out of date. Select all, right-click Bulk update, and pick the script.
- 🔷 That script is what runs. The script manager holds it, and the run is a task.
- 🔷 Broadcast does not cross the internet. The next piece is the startup window offering a typed address when no broadcast is found.
- ℹ️ The Assets page is [5.5](5.5-controller-user-interface.md). The script and the task are [7.0](7.0-tasks.md) and [7.1](7.1-tasks-implementation.md).

## The path

- 🔷 `✔️` Install the server on the live machine.
  - `argusrm-server` installs, enables, and starts `argusrm-server.service`.
  - ℹ️ [install-packages.md](../install-packages.md). The unit is `packaging/systemd/argusrm-server.service`.
- 🔷 `✔️` On that server, run the controller as root.
  - It prints the six-digit number and opens the port.
  - ℹ️ The command in the tree is `sudo argus-controller --pin`. With no desktop, `sudo argus-controller` alone prints usage. [3.0 Phase 2](3.0-server.md).
- 🔷 `⏳` On this desktop, add that server and register the controller.
  - This is the next piece. See below.
- 🔷 `⏳` Register an agent against that server.
  - A box that cannot hear the broadcast still needs the server address.
  - The desktop controller is the piece specified here. The agent address waits until that window works.
- 🔷 `✔️` Log in with the certificate from that registration.
  - Saved servers are tried from `connections.json`. One that answers opens the main window over TLS.
  - ℹ️ [5.2](done/5.2-DONE-controller-user-registration.md), [5.3 Phase 1](5.3-controller-remote-registration.md).
- 🔷 `✅` After login, list the agents.
  - The Agents grid shows them. Five were connected.
  - ℹ️ [5.6](5.6-agent-page.md).
- 🔷 `⏳` Open Assets. The top of the page tabs it.
  - Machines, then Software.
  - 💩 The control is `Adw.ViewSwitcher`, on the page. The window header stays the title only.
  - ℹ️ [5.5 Assets](5.5-controller-user-interface.md).
- 🔷 `⏳` Machines lists the machines.
  - A machine may be real or virtual. Both are this tab.
  - 💩 One list. No second tab that splits real from virtual.
- 🔷 `⏳` Software lists the software. An operating system is one type.
- 🔷 `⏳` Filter Software to operating system, and to needs updating.
  - What is left is the Debian rows that are out of date.
  - 💩 A name filter of Debian, when another operating system is also behind.
- 🔷 `⏳` Select all of that filter.
  - The header tick selects every row in the current filter.
- 🔷 `⏳` Right-click, Bulk update, then pick the script.
  - The Debian update script is the one this aim runs.
  - The run is one task, one target per machine those rows belong to.
  - 💩 The grid action bar can offer the same Bulk update. This path is the right-click.
  - ℹ️ `Task.create`, `Task.target`, and `Task.approve` are ready in [7.1](7.1-tasks-implementation.md).

## Script manager

- 🔷 `✔️` The server already has the library calls.
  - `Script.list`, `Script.read`, `Script.create`, `Script.update`.
  - `Script.enable` and `Script.disable` say which agents may run a script.
  - `ScriptRepository.clone`, `pull`, `list`, and `remove` are the extra libraries.
  - `scripts/` is repository id `0`.
- 🔷 `⏳` The system-update script has to be in that library before Bulk update can run it.
  - 💩 The first copy is created in `scripts/` through `Script.create`, path `bin/debian/update`.
  - 💩 The body is the package-manager update used on these Debian boxes. The exact lines wait until this step.
- 🔷 `⏳` The controller has no page for that library yet.
  - Scripts is the first page in [5.5](5.5-controller-user-interface.md).
  - ℹ️ [7.1 Phase 3](7.1-tasks-implementation.md).
- 🔷 `⏳` Running it is the task, not a direct command from the page.
  - `--command` already runs one line on one agent. That is not this update.

## Next — the startup window, used again for another server

- 🔷 `⏳` Set up the server first. Then register this desktop against it.
- 🔷 `⏳` The window that comes up at startup is the one used again to register another server.
  - First run, and again after this desktop is already registered.
  - `Argus.Controller.Bootstrap`.
- 🔷 `⏳` It looks for the broadcast, then asks for the six-digit number.
- 🔷 `⏳` When no broadcast is found, that same window offers a place to type the server's IP address.
  - Connect checks that the address answers. It does not register yet.
  - When it answers, the number entry appears, the same as after a broadcast.
  - The number is the one printed on the server. There is no password prompt.
- 🔷 `⏳` Typing an address also shows a tick: this desktop is on a fixed IP. The tick starts off.
- 🔷 `⏳` Connect with an address and the tick left off shows a warning before anything else.
  - Using a controller on a non-fixed IP address will not work, because you will have to register again every time.
  - It is better to set up a VPN.
- 🔷 The server side stays the command line. That path does not ask about a fixed IP.
- 🔷 Broadcast stays for a machine that can hear it.
- ℹ️ Today the empty startup page is "Log in to local machine" and "Connect a remote machine". Connect a remote machine only scans. The cog menu's "Register controller" opens the number on the server you are already using. It does not bring this startup window back.
- ℹ️ While the number is open, the port accepts the connection. After registration, a registered agent or controller stays allowed when this server can reach that machine. A private address and a public address are the same case. [6.1](6.1-nftables-firewall.md).
- ℹ️ The warning exists because the server remembers the address it saw. A later address does not match, so that desktop has to register again.
- 💩 After the warning is dismissed, Connect still checks the address. The warning does not refuse it.
- 💩 The field is an IP address. The port is the server port unless the field includes one.

## LLM notes

- 🚫 Do not treat `--command` as the system update.
- 🚫 Do not start this update from the Agents grid or from Machines. The rows are on Software.
- 🚫 Do not treat the operating system as only a column on a machine. It is a type of software.
- 🚫 Do not put the Machines / Software switcher in the window header. It sits at the top of the Assets page.
- 🚫 Do not remove broadcast. A typed address is the path when this desktop cannot hear it.
- 🚫 Do not make a second registration window. Adding another server uses the startup window again.
- 🚫 Do not prompt for a password on Connect. The six-digit number is the existing PIN entry.
- 🚫 Do not put the fixed-IP tick on `sudo argus-controller --pin`. That path is the server.
- 🚫 Do not write the `bin/debian/update` body in this plan. The lines are chosen when that script is added.
