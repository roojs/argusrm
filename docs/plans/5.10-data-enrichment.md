# 5.10 Data enrichment

**Status:** ✔️ Phase 1 is in the tree. ✔️ Phase 2 is in the tree. Phase 3 sends the names that need updating.

## Purpose

- 🔷 Available packages. An installed package has an update waiting.
- 🔷 Phase 1 stores the columns. Phase 2 reads the host, by target. Phase 3 sends the names that need updating. The server sets the flags.
- ℹ️ An install or a removal stays a full list. [5.9.1](done/5.9.1-DONE-assets-software-data.md). The OS release is [5.11](5.11-os-update.md).
- ℹ️ Column names are [4.0](4.0-data-types.md). The software list is [5.9](5.9-assets-software.md).

## Phases

- 🔷 ✔️ Phase 1. The columns. `pkgs_updated` and `pkgs_status` on `os_version`. `update_available` on `deb_packages` and on `rpm_packages`.
- 🔷 ✔️ Phase 2. The read. `agent/linux/UpdatesAvailable.vala` and `agent/Win32/UpdatesAvailable.vala`, the same split as `PackageMonitor`. APT is one target. DNF is one target. SUSE is not chosen. Windows and Android do not read a list.
- 🔷 ⏳ Phase 3. The agent sends the package names that need updating. The server sets `update_available`, `pkgs_status`, and `pkgs_updated`.
- ℹ️ The machine list already has the S/W status column. It stays empty until these columns are stored. [5.8](5.8-assets-page.md).

## Phase 1 ✔️

The columns. No read, and no send. There is no data to migrate. An existing database gains the column with `ALTER TABLE`. A new database gets it from `CREATE TABLE`.

- 🔷 `os_version` stores `pkgs_updated`. The last time that host checked its installed packages. Not one package.
- 🔷 `os_version` stores `pkgs_status`. Those packages are up to date.
- ℹ️ `os_updated` and `os_status` are the OS release. The server writes them. Debian's release file is [5.11](5.11-os-update.md). This plan does not read it.
- 🔷 `deb_packages` stores `update_available` on each installed package.
- 🔷 `rpm_packages` stores `update_available` on each installed package.
- 🔷 `programs` does not gain `update_available`.
- 🔷 `pkgs_updated` is the unix time of that check. The check runs twice a day. A check that finds the same answer still moves the time. `0` means the check has not happened.
- 💩 `pkgs_status` is `1` when up to date and `0` when not. `update_available` is `1` when one package has an update waiting.
- 💩 `compare` skips the three new properties. A full `OSQuery.sync` does not send them. A stored `1` against `0` would mark the row changed and clear the flag.

Edits are **Remove** / **Replace with** / **Add** from the tree. Verify the surrounding lines before applying.

### 1. `agent/linux/UpdatesAvailable.vala` — the APT and DNF read

**Why:** the Linux agent reads the pending packages. `check` follows `package_manager`.

**Where:** new file, next to `agent/linux/PackageMonitor.vala`. The desktop agent and the command-line agent compile it. The Windows agent does not.

**Depends on:** Phase 1. This file does not write the columns.

#### Add — new file `agent/linux/UpdatesAvailable.vala`

```vala
/*

 * along with this library; if not, write to the Free Software Foundation,
 * Inc., 51 Franklin Street, Fifth Floor, Boston, MA  02110-1301  USA
 */

namespace Argus.Agent
{
	/**
	 * Read which installed packages have an update waiting.
	 *
	 * {@link check} uses
	 * {@link Argus.Shared.OSQuery.OsVersion.package_manager}.
	 * APT runs {@link check_apt}. DNF runs {@link check_rpm}.
	 * An empty list is up to date. A failure throws. The
	 * commands read the lists already on the host.
	 *
	 * == Example ==
	 *
	 * {{{
	 * var pending = new Argus.Agent.UpdatesAvailable();
	 * var names = pending.check(application.os_version);
	 * }}}
	 */
	public class UpdatesAvailable : GLib.Object
	{
		/**
		 * Pending package names for this operating system.
		 *
		 * APT calls {@link check_apt}. DNF calls {@link check_rpm}.
		 * Any other value throws.
		 *
		 * @param os_version startup ''os_version'' row
		 * @return package names, empty when none are waiting
		 */
		public Gee.ArrayList<string> check(
			Argus.Shared.OSQuery.OsVersion os_version
		) throws GLib.Error
		{
			switch (os_version.package_manager()) {
				case Argus.Shared.OSQuery.PackageManager.APT:
					return this.check_apt();
				case Argus.Shared.OSQuery.PackageManager.DNF:
					return this.check_rpm();
				default:
					throw new GLib.IOError.FAILED("no package check for this operating system");
			}
		}

		/**
		 * Packages apt would upgrade from the local lists.
		 *
		 * The command is ''apt-get -s -qq upgrade'' with locking
		 * disabled. Each ''Inst'' line is one package. The name
		 * is the second field. A non-zero exit throws.
		 *
		 * @return package names, empty when none are waiting
		 */
		public Gee.ArrayList<string> check_apt() throws GLib.Error
		{
			var child = new GLib.Subprocess.newv({
				"apt-get", "-o", "Debug::NoLocking=true",
				"-s", "-qq", "upgrade"
			}, GLib.SubprocessFlags.STDOUT_PIPE);
			string? stdout_text = null;
			var read = child.communicate_utf8(null, null, out stdout_text, null);
			if (!read || !child.get_if_exited()) {
				throw new GLib.IOError.FAILED("apt-get did not exit");
			}
			if (child.get_exit_status() != 0) {
				throw new GLib.IOError.FAILED("apt-get exited %d".printf(child.get_exit_status()));
			}
			var names = new Gee.ArrayList<string>();
			var output = stdout_text != null ? stdout_text : "";
			foreach (var line in output.split("\n")) {
				if (!line.has_prefix("Inst ")) {
					continue;
				}
				var fields = line.split(" ");
				if (fields.length < 2 || fields[1] == "") {
					continue;
				}
				names.add(fields[1]);
			}
			return names;
		}

		/**
		 * Packages dnf would upgrade from the local cache.
		 *
		 * The command is ''dnf check-update --cacheonly''.
		 * Exit ''100'' means updates are waiting. Exit ''0''
		 * is an empty list. Any other exit throws. The name
		 * is the first field, without the arch after the
		 * last dot.
		 *
		 * @return package names, empty when none are waiting
		 */
		public Gee.ArrayList<string> check_rpm() throws GLib.Error
		{
			var child = new GLib.Subprocess.newv({
				"dnf", "check-update", "--cacheonly"
			}, GLib.SubprocessFlags.STDOUT_PIPE);
			string? stdout_text = null;
			var read = child.communicate_utf8(null, null, out stdout_text, null);
			if (!read || !child.get_if_exited()) {
				throw new GLib.IOError.FAILED("dnf did not exit");
			}
			var code = child.get_exit_status();
			if (code != 0 && code != 100) {
				throw new GLib.IOError.FAILED("dnf exited %d".printf(code));
			}
			var names = new Gee.ArrayList<string>();
			var output = stdout_text != null ? stdout_text : "";
			foreach (var line in output.split("\n")) {
				var fields = line.split(" ");
				if (fields.length < 2 || fields[0] == "") {
					continue;
				}
				var token = fields[0];
				var dot = token.last_index_of(".");
				if (dot < 1) {
					continue;
				}
				names.add(token.substring(0, dot));
			}
			return names;
		}
	}
}
```

### APT

Debian, Ubuntu, and eLxr. One `check_apt`. `update_available` goes on `deb_packages`.

- 🔷 The package read is `apt-get -o 'Debug::NoLocking=true' -s -qq upgrade`.
- 🔷 Each `Inst` line is one package name in the list the agent sends. The server sets `update_available`. `pkgs_status` is up to date when that list is empty.
- ℹ️ On this host that line is `Inst chromium [156.0.8078.79~linuxmint1+mint22.3] (157.0.8103.50~linuxmint1+mint22.3 freeshell.de [amd64])`. The name is the second field. A line that does not start with `Inst ` is left out.
- ℹ️ `apt-daily.timer` already refreshes the lists twice a day. The agent reads that cache.
- 💩 Ubuntu uses that same read.
- 💩 eLxr uses that same read. Confirm eLxr is this family before building.

### DNF

Fedora, RHEL, and CentOS. One `check_rpm`. `update_available` goes on `rpm_packages`.

- 💩 The package read is `dnf check-update --cacheonly`. That stays on `/var/cache/dnf`.
- 💩 Exit `100` means updates are waiting. Exit `0` is an empty list. Any other exit throws.
- 💩 The name is the first field, with the arch after the last dot removed. `kernel.x86_64` is `kernel`.
- 💩 RHEL and CentOS use that same read.

### SUSE

- 💩 The package read is not `dnf`. SUSE is `zypper`. The command is not chosen. `package_manager` stays `UNKNOWN`.

### Windows

- 🔷 Windows has no file of software that needs updating. `update_available` is not added to `programs`.
- 💩 `pkgs_status` stays empty. There is no pending-update list to read.

### Android

- ℹ️ Android does not query installed packages. [5.9.1](done/5.9.1-DONE-assets-software-data.md).
- 💩 `pkgs_status` stays empty. There is no package read.

## Phase 3

The agent sends the package names that need updating. The server decides what to store. This is not a package snapshot, and it is not `OSQuery.sync`.

- 🔷 The agent posts the full package list with `OSQuery.sync` for an install or a removal. [5.9.1](done/5.9.1-DONE-assets-software-data.md). This phase does not use that call.
- 🔷 The check runs twice a day. The agent sends the names `check` returned. An empty list means nothing needs updating.
- 🔷 The server receives that list and sets the stored columns. The agent does not send `update_available` or `pkgs_status`.
- ℹ️ The call is not chosen. The payload is the names, not package rows.
- 💩 The server writes `pkgs_updated` from the check time, including a check that finds the same names.
- 💩 A name in the list sets `update_available` to `1` on that agent's stored row. A stored package of that class left off the list is set back to `0`.
- 💩 `pkgs_status` is `1` when the list is empty and `0` when it is not. The package class is the one `package_manager` already chose. APT is `deb_packages`. DNF is `rpm_packages`.
- 💩 The package circle comes from `pkgs_status`. Green when up to date, red when not. Empty when `pkgs_updated` is `0`.

## LLM notes

- 🚫 Do not monitor installs here. A package added, removed, or a version that moved is [5.9.1](done/5.9.1-DONE-assets-software-data.md).
- 🚫 Do not check whether the OS release is current. That is [5.11](5.11-os-update.md).
- 🚫 Do not paint the OS circle from `update_available`. That read is the package circle.
- 🚫 Do not send the pending names through `OSQuery.sync`. That call is the full package list. A row left out of it is marked deleted.
- 🚫 Do not have the agent set `update_available` or `pkgs_status`. The server does that from the names.
- 🚫 Do not have the helper run the update. The lists are already on the host.
- 🚫 Do not add `update_available` to `programs`.
- 🚫 Do not add the read classes as a mock left out of `agent/meson.build`.
- 🚫 Do not start phase 2 before phase 1.
- 🚫 Do not mark a ✔️ line ✅.
