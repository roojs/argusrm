## Purpose

- 🔷 Data enrichment is available packages. An installed package has an update waiting.
- 🔷 This plan is that read, and the send. Package update and OS update are separate.
- ℹ️ Installed rows changing is [5.9.1](5.9.1-assets-software-data.md). A package added, removed, or a version that moved. This plan is not that.
- ℹ️ The OS release check is [5.11](5.11-os-update.md). This plan is not that.
- ℹ️ Column names are [4.0](4.0-data-types.md). The software list is [5.9](5.9-assets-software.md).

---

## Shared

- 🔷 `os_version` stores `package_updated`. When that host last checked installed packages.
- 🔷 `os_version` stores `package_status`. Installed packages are up to date.
- 🔷 `deb_packages` stores `update_available` on each installed package.
- 🔷 `rpm_packages` stores `update_available` on each installed package.
- 🔷 S/W status on the machine list is `package_status`. [5.8](5.8-assets-page.md).
- 🔷 Needs updating on a package row is `update_available`.
- ℹ️ These columns are not stored yet. Add them. There is no data to migrate.
- 💩 `package_updated` is the unix time, `0` when that check has not happened. `package_status` is `1` when up to date and `0` when not. `update_available` is `1` when a package has an update waiting.
- 💩 The package circle comes from the same read as `update_available`, so the two do not disagree.
- 💩 Green when up to date, red when not. Empty when that check has not run.
- ℹ️ The helper reads the update state already on the host. It does not run the update.

## Classes

A mock. Not in the build.

- 🔷 The `os_version` query keeps that row on the agent. `Application.os_version`.
- 🔷 ✔️ `OsVersion.package_manager` switches on `platform_like`, then `platform`. It returns `PackageManager.APT`, `PackageManager.DNF`, `PackageManager.WIN`, or `PackageManager.UNKNOWN`. SUSE is `UNKNOWN`.
- 🔷 `UpdatesAvailable.check` switches on that value. `PackageManager.APT` calls `check_apt`. `PackageManager.DNF` calls `check_rpm`. Each parses its own output.
- 🔷 `check`, `check_apt`, and `check_rpm` return a `Gee.ArrayList` of package names. An empty list is up to date. A failure throws. Windows and unknown throw. SUSE is unknown. The command is not chosen.
- 🔷 Windows is the same class in `agent/Win32/UpdatesAvailable.vala`. `check` returns false. There is no pending-update list.
- 🔷 Neither file is in `agent/meson.build`. Nothing calls `check`.
- 🚫 Do not add these files to the build from this mock.

## Send

- 🔷 The agent checks twice a day.
- 🔷 It sends only when something changed.
- 🔷 The send is that change. Not the full package list.
- ℹ️ A change here is `update_available` flipping, or `package_status` changing. An install or a removal is [5.9.1](5.9.1-assets-software-data.md).
- ℹ️ `Row.sync_rows` treats the array as the whole set for that agent. A row left out is deleted. `OSQuery.sync` is that full set.
- 💩 The send is `package_status` and `package_updated` on the one `os_version` row when either changed, and the package rows whose `update_available` changed. It is not `OSQuery.sync`.

## Debian

- 🔷 The package read is `apt-get -o 'Debug::NoLocking=true' -s -qq upgrade`.
- 🔷 Each `Inst` line is one package with `update_available`. `package_status` is up to date when that list is empty.
- ℹ️ `apt-daily.timer` already refreshes the lists twice a day. The agent reads that cache. It does not run the upgrade.

## Windows

## LLM notes

- 🚫 Do not monitor installs here. A package added, removed, or a version that moved is [5.9.1](5.9.1-assets-software-data.md).
- 🚫 Do not check whether the OS release is current. That is [5.11](5.11-os-update.md).
- 🚫 Do not paint the OS circle from `update_available`. That read is the package circle.
- 🚫 Do not send the full package list. Send only when an available-update flag changed.
- 🚫 Do not send a partial package list through `OSQuery.sync`. A row left out is deleted.
- 🚫 Do not have the helper run the update. The lists are already on the host.
- 🚫 Do not add `update_available` to `programs`.
- 🚫 Do not build this before the data and the pages.
- 🚫 Do not take the startup software query out while that later pass is still open.
- 🚫 Do not mark a ✔️ line ✅.
