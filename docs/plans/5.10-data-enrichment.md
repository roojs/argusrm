## Columns

Helpers fill these when the agent fetches. The server stores them.

- 🔷 `os_version` stores `os_updated`. When that host last checked whether the OS version is current.
- 🔷 `os_version` stores `os_status`. The OS version is up to date. Not the installed packages.
- 🔷 `os_version` stores `package_updated`. Last package update. When that host last checked installed packages.
- 🔷 `os_version` stores `package_status`. Installed packages are up to date.
- 🔷 `deb_packages` stores `update_available` on each installed package.
- 🔷 `rpm_packages` stores `update_available` on each installed package.
- 🔷 The two host circles are in [5.8](5.8-assets-page.md). OS status is the OS version. S/W status is installed packages.
- 🔷 Needs updating on a package row is `update_available`.
- ℹ️ The helper reads the update state already on the host. It does not run the update.
- ℹ️ `deb_packages` from osquery is `/var/lib/dpkg`. `apt_sources` is the repository lines in `/etc/apt`. The OS circle is that kind of check: is the OS version current.
- ℹ️ [8.0](8.0-nagios.md) still names `check_apt`. These columns are not that plugin.
- ℹ️ These columns are not stored yet. Add them. There is no data to migrate.
- 💩 `os_updated` and `package_updated` are the unix time, `0` when that check has not happened. `os_status` and `package_status` are `1` when up to date and `0` when not.
- 💩 The package circle comes from the same read as `update_available`, so the two do not disagree.
- 💩 The OS circle does not. A current release can still have packages waiting.
- 💩 Green when up to date, red when not. Empty when that check has not run.

## Refresh

Startup may send the full tables. A later refresh does not send rows that have not changed.

- 🔷 The startup send stays a full snapshot. That query stays for now. The installed-package sync is [5.9.1](5.9.1-assets-software-data.md). The list is [5.9](5.9-assets-software.md).
- ℹ️ The sync timestamps, and the osquery event feed that triggers a later package sync, are [5.9.1](5.9.1-assets-software-data.md). This section is the update columns.
- 🔷 The refresh is differential.
- 🔷 It includes the update columns and the installed packages that changed.
- ℹ️ A changed install is a package added, a package removed, or a version that moved. An `update_available` that flipped is a change too.
- ℹ️ `Row.sync_rows` treats the array as the whole set for that agent. A row left out is deleted. `OSQuery.sync` is that full set.
- 💩 The refresh sends the one `os_version` row, the package rows that changed, and the keys of packages that were removed. It is not `OSQuery.sync`.
- 🔷 ⏳ When the refresh runs is not set.
- 🔷 ⏳ `logged_in_users` is the same kind of question. The machine column only reads rows already stored. Startup posts the table. How a later login reaches the server is not designed. [5.8](5.8-assets-page.md) chunk 5.

## LLM notes

- 🚫 Do not call the OS circle a package update. The OS circle is the OS version.
- 🚫 Do not paint the OS circle from `update_available`. That read is the package circle.
- 🚫 Do not have the helper run the update. The lists are already on the host.
- 🚫 Do not send a partial package list through `OSQuery.sync`. A row left out is deleted.
- 🚫 Do not add `update_available` to `programs`.
- 🚫 Do not build this before the data and the pages.
- 🚫 Do not take the startup software query out while that later pass is still open.
- 🚫 Do not fill the machine user column from the agent. [5.8](5.8-assets-page.md) reads the stored rows.
- 🚫 Do not mark a ✔️ line ✅.
