## Purpose

- 🔷 A **Connect to desktop** button on the machine General tab.
- 🔷 The button opens a new window that is visual remote control of that machine.
- 🔷 Argus enables Windows Remote Desktop on the machine so the machine can accept it.
- 🔷 Argus tunnels the Remote Desktop bytes between that machine and the controller.
- 🔷 The controller side is a Linux viewer of that same protocol.
- 🔷 ⏳ This plan records that both parts are feasible. It does not implement them.
- ℹ️ The General tab is `controller/tab/Asset/Machine/General.vala`, inside `controller/tab/Asset/Machine/Detail.vala`.
- ℹ️ The controller is GTK 4 and libadwaita. `controller/meson.build`.
- ℹ️ The Windows agent is the service in `agent/Win32/Service.vala`. It already holds a TLS session to the server.

---

## Feasibility

- 🔷 Enabling and tunneling are one feature. The tunnel has nothing to connect to until Remote Desktop is on. Enabling alone still leaves the controller with no route to port 3389.
- ℹ️ Enabling is feasible on Windows Pro, Enterprise, Education, and Server. The service runs as the machine's service account, which can change the Terminal Server setting, start Remote Desktop Services, and open the firewall group.
- ℹ️ Enabling is not feasible on Windows Home. That edition has no supported way to accept an incoming Remote Desktop session. Starting the service does not add the feature.
- ℹ️ Tunneling is feasible. Remote Desktop is a two-way TCP byte stream on port 3389. The agent is already on the machine. It can open `127.0.0.1:3389` and carry those bytes to the server on a second connection.
- ℹ️ That second connection is its own socket. The app socket stays the RPC session. `Application.open_connection` keeps that one `TlsClient` and `watch` reads frames for the life of it. Switching that socket to raw bytes would stop commands and osquery posts.
- ℹ️ The download socket is the precedent. It is a separate listen, the same client certificate, and a transfer there does not clog the app socket. `server/Net/Download.vala`. The relay is the same idea, for this stream.
- ℹ️ The person at the controller still signs in as a Windows user. Enabling the service does not remove Network Level Authentication, and the password is not something Argus stores.
- ℹ️ One interactive session on a client Windows edition. The connection takes the console. The person sitting at the machine is signed out of that console.

## Where the button would sit

- 🔷 On the General tab of one machine. Not on the machine list. Not on Agents.
- 🔷 Label: Connect to desktop.
- 🔷 It opens another window. It does not replace the General tab.
- ℹ️ General is a vertical list of expanders. It has no bar of its own.
- ℹ️ `Detail` already has a bar. That bar is the tab toggles (General, Users, packages, Interfaces, Storage).
- ℹ️ The window header bar is the title only. A button does not go there.
- 💩 ⏳ The button sits on a bar that belongs to the General page, above the key-value list.
- 💩 ⏳ The button is shown when `os_version.platform` is `windows` and the edition can host Remote Desktop. Home gets a notice.

---

## What Argus enables

- 🔷 Turn incoming Remote Desktop on for that machine.
- ℹ️ The switch Windows already has. Registry value `fDenyTSConnections` under `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server` set to `0`. Remote Desktop Services (`TermService`) set to start, and started. The firewall group "Remote Desktop" is the part that opens TCP 3389 to the LAN.
- ℹ️ The agent does none of this today.
- 💩 ⏳ Leave Network Level Authentication on.
- 💩 ⏳ The tunnel only needs the service listening on localhost. Opening 3389 on the LAN is a separate choice. Default is leave the LAN rule closed, so the only client is the Argus tunnel.

---

## What Argus tunnels

- 🔷 The Remote Desktop protocol bytes, not a second remote-desktop product.
- 🔷 The relay has its own listen socket. It is not the app socket, the download socket, or the registration socket.
- 🔷 The agent opens a second connection to that socket, with the client certificate it already has. The app connection stays up.
- 🔷 After the server has matched that certificate, the new connection is switched to raw bytes and stays the transport until the window closes.
- 🔷 The controller opens a second connection to the same socket. The server splices the two. FreeRDP talks to a localhost port on the controller, and that port is the controller's end of the splice.
- ℹ️ The agent dials out, the same way it dials the app socket, so the machine does not accept a new inbound port.
- ℹ️ A short notification on the app socket is what tells the agent to open the second connection. The desktop bytes do not travel on that notification.
- ℹ️ The session ends when the window closes, and when either relay connection drops.
- ℹ️ The new port has to sit on the same allowlist as the app socket, or the agent cannot dial it.
- 🔷 FreeRDP is the viewer. It asks for the Windows password.
- 🔷 No drive redirection.
- 🔷 Clipboard sharing can wait. It is not required to see and control the desktop.
- 🔷 Audio is unlikely. It is not part of this plan.

---

## Verdict

- 🔷 Argus can enable Remote Desktop on Pro, Enterprise, Education, and Server, and can tunnel that protocol to the Linux controller.
- 🔷 Windows Home is the stop. There is nothing supported to enable.
- 🔷 The button and the window are the small part. The enable steps and the byte channel are the work, and they are a design change (API and security) when implementation starts.
- 💩 ⏳ Linux machines are a later plan. GNOME Remote Desktop and xrdp also speak this protocol, so the same tunnel could reach them after Windows works.

## Open before any code

- 🔷 ⏳ Approve enabling the service and adding the byte tunnel. Both are feasible. Neither is written yet.
- 💩 ⏳ LAN firewall stays closed. Only the tunnel connects.
- 💩 ⏳ The Android controller does not get this button.

## LLM notes

- Do not patch `termsrv.dll` or otherwise unlock Remote Desktop on Windows Home.
- Do not turn Network Level Authentication off.
- Do not put the desktop bytes on `agent.run` or the command log files.
- Do not switch `Application.connection` to raw bytes. The relay is a second `TlsClient` to the relay socket.
- Do not add drive redirection.
