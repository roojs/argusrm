# 5.11 OS update

**Status:** ✔️ Phase 1 is in the tree. Phase 2 is [5.11.1](5.11.1-os-update-server.md). Phases 3 and 4 are proposed.

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**.

**Parent:** [5.8-assets-page.md](5.8-assets-page.md)

---

## Purpose

- 🔷 Whether the installed OS release is current.
- 🔷 The server checks, once a week. A new release is the same fact for every machine on that release.
- 🔷 Only fetch release files for OS versions actually stored in `os_version`.
- 🔷 Store the last fetch time in `os_version.os_updated`. No separate store or table tracks fetch times.
- ℹ️ Available packages are [5.10](5.10-data-enrichment.md). This plan is not that.
- ℹ️ Column names are [4.0](4.0-data-types.md).

---

## Phases

- 💩 ✔️ Phase 1. Shared columns and sync. `os_updated`, `os_status`, and `reboot_required` on `os_version`.
- 💩 ⏳ Phase 2. Server weekly check. [5.11.1](5.11.1-os-update-server.md).
- 💩 ⏳ Phase 3. Windows `reboot_required` read in `Execute.sync_table` before `OSQuery.sync`.
- 💩 ⏳ Phase 4. Machine list. `SystemInfo.list` joins `os_updated`, `os_status`, and `reboot_required`, `Base` draws `status` and `date`, and `Filters.SystemInfo` matches `OS needs update`.

---

## Phase 1 ✔️

- 🔷 `os_version` stores `os_updated`. When the server last checked whether that OS release is current.
- 🔷 `os_version` stores `os_status`. The OS version is up to date. Not the installed packages.
- 🔷 `os_version` stores `reboot_required`. A restart is waiting.
- 🔷 The server writes `os_updated` and `os_status`. Once a week. It reads the `os_version` rows already stored.
- 🔷 The agent does not send `os_status`.
- 🔷 Each agent has one `os_version` row. `OsVersion.sync` accepts only a single `OsVersion` row (`rows.size == 1`) and inserts or updates that agent's stored row directly without `sync_rows` or nested loops.
- 🔷 OS status on the machine list is `os_status`. [5.8](5.8-assets-page.md).
- ℹ️ These columns are not stored yet. Add them. There is no data to migrate.
- 💩 `os_updated` is the unix time, `0` when that check has not happened. `os_status` is `1` when up to date, `0` when not, and `-1` when checked against a file that did not list that release.
- 💩 `reboot_required` is `1` when a Windows restart is waiting and `0` otherwise. Confirm the name before building.
- 💩 `OsVersion.bin_write_prop` is not overridden; `Row.bin_write_prop` skips `os-updated` and `os-status` in its `switch (prop.name)` alongside `id` and `agent-id`.
- 💩 `AgentInfo.compare` skips `os-updated` and `os-status`. It keeps `reboot-required` so a changed reboot flag updates the stored row.
- 🔷 `OsVersion.sync` uses `SQ.Interface.copy_from` when merging the incoming snapshot onto the stored row (`pkgs_updated` and `pkgs_status` stay excluded; `os_updated` and `os_status` stay excluded while `platform`, `version`, and `codename` match, and reset to `0` on an OS upgrade).

```vala
	/**
	 * One ''os_version'' row.
	 *
	 * Each registered agent stores one operating-system row,
	 * joined onto {@link SystemInfo.list} for the Machines
	 * page.
	 */
	public class OsVersion : Row
	{
		/**
		 * Store one agent's ''os_version'' row.
		 *
		 * Each agent has one operating-system row. A snapshot
		 * that does not carry a single {@link OsVersion} is
		 * rejected. Stored package check fields stay, and
		 * stored OS check fields stay while ''platform'',
		 * ''version'', and ''codename'' match.
		 *
		 * @param db Argus database
		 * @param agent_id registered agent
		 * @param rows single-row ''os_version'' snapshot
		 * @return true when ''rows'' has one ''OsVersion'' row
		 */
		public override bool sync(SQ.Database db, int64 agent_id, Gee.ArrayList<AgentInfo> rows)
		{
			if (rows.size != 1 || rows.get(0).get_type() != typeof(OsVersion)) {
				return false;
			}
			var newer = (OsVersion) rows.get(0);
			newer.agent_id = agent_id;
			var query = new SQ.Query<OsVersion>(db, "os_version");
			var stored = new Gee.ArrayList<OsVersion>();
			var int_binds = new Gee.HashMap<string, int>();
			int_binds.set("agent_id", (int) agent_id);
			query.selectWhere("WHERE agent_id = $agent_id", int_binds, null, stored);
			var now = (int) new GLib.DateTime.now_utc().to_unix();
			if (stored.size == 0) {
				newer.id = 0;
				newer.added_dt = now;
				newer.updated_dt = 0;
				newer.deleted_dt = 0;
				query.insert(newer);
				return true;
			}
			var old = stored.get(0);
			if (old.deleted_dt == 0 && old.compare(newer)) {
				return true;
			}
			var updated = new OsVersion();
			updated.copy_from(old, {});
			string[] keep = {
				"id", "added-dt", "updated-dt", "deleted-dt",
				"pkgs-updated", "pkgs-status"
			};
			if (old.platform == newer.platform &&
				old.version == newer.version &&
				old.codename == newer.codename) {
				keep += "os-updated";
				keep += "os-status";
			}
			updated.copy_from(newer, keep);
			updated.deleted_dt = 0;
			updated.updated_dt = now;
			query.updateOld(old, updated);
			return true;
		}
```

## Phase 2 — Server weekly check

The server weekly check is [5.11.1](5.11.1-os-update-server.md).

- 🔷 Only fetch release CSVs for platforms actually present in active `os_version` rows (`deleted_dt = 0` and `agent_id` in `agent`).
- 🔷 `os_version.os_updated` records when we last fetched. A platform whose active rows were all checked within the last seven days is not fetched again.
- ℹ️ Debian, Ubuntu, and eLxr use `distro-info-data` CSVs. Fedora, RHEL, CentOS, SUSE, and Android leave `os_status` empty until a release file exists.

## Phase 3 — Windows

- 🔷 ⏳ No release file yet. `os_status` stays empty until it exists.
- 🔷 `os_version` stores `reboot_required`. A restart is waiting.
- 🔷 The Windows agent sets `reboot_required` on the `os_version` row before the send.
- 🔷 The flag is `1` when either key is present, and `0` when neither is.
  - `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\WindowsUpdate\Auto Update\RebootRequired`
  - `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\CurrentVersion\Component Based Servicing\RebootPending`
- ℹ️ The agent reads those two keys. The `registry` table is not synced.
- ℹ️ Linux leaves `reboot_required` at `0`.
- 💩 `Execute.sync_table` checks both keys with `RegOpenKeyExW` under `#if WINDOWS` (`advapi32` is already linked in `agent/meson.build`).
