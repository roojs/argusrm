## Assets — Machines

One row is the machine. Many rows are a later drill-down. The lists below stay here either way.

### One row

`system_info` and `os_version` are one row per host. These are the machine columns.

- ✅ starts visible.
- hidden starts off, and can be turned on.
- ℹ️ A tick here is the display choice. The page is not built.

`system_info`. Stored.

- ✅ `hostname` — host name.
- hidden `local_hostname` — host name without a domain.
- ✅ `computer_name` — the Windows computer name.
- hidden `uuid` — hardware UUID.
- ✅ `hardware_vendor` — maker.
- hidden `hardware_model` — model.
- hidden `hardware_version` — hardware version.
- hidden `hardware_serial` — serial.
- hidden `board_vendor` — motherboard maker.
- hidden `board_model` — motherboard model.
- hidden `board_version` — motherboard version.
- hidden `board_serial` — motherboard serial.
- ✅ `physical_memory` — bytes of RAM.
- hidden `cpu_brand` — CPU name.
- hidden `cpu_type` — CPU family code.
- hidden `cpu_subtype` — CPU subtype code.
- hidden `cpu_physical_cores` — physical cores.
- hidden `cpu_logical_cores` — logical cores.
- hidden `cpu_microcode` — microcode revision.

`os_version`. Stored. The installed system.

- ✅ `name` — Debian GNU/Linux, Windows.
- ✅ `version` — 12, 11.
- hidden `major` — first numeric part.
- hidden `minor` — second numeric part.
- hidden `patch` — third numeric part.
- hidden `build` — build string.
- hidden `platform` — debian, rhel, windows.
- hidden `platform_like` — the family. Ubuntu reports debian.
- hidden `codename` — bookworm.
- hidden `arch` — x86_64, arm64.

`os_version`, not stored yet. Filled in [5.10](5.10-data-enrichment.md). No migration. These columns are not on a server yet.

- hidden `os_updated` — when the OS version check last ran. A date.
- ✅ `os_status` — OS status. The OS version is up to date. Not the installed packages. A circle.
- hidden `package_updated` — last package update. When the package check last ran. A date.
- ✅ `package_status` — S/W status. Installed packages are up to date. A circle.
- 🔷 The headers are OS status and S/W status.
- 🔷 Green when that one is up to date.
- 💩 Red when it is not. Empty when that check has not run.

### Fake column

- ✅ Logged-in user. Not a stored column. The first `logged_in_users` row, its `user`.
- ℹ️ The rest of that table is many rows. It is not a set of machine columns.

### Many rows

Secondary information. A later phase drills down into a machine. Not the first stage. The columns stay documented here.

`cpu_info`. One row per processor. Stored.

- ℹ️ `model` — CPU model.
- ℹ️ `manufacturer` — maker.
- ℹ️ `device_id` — which processor.
- ℹ️ `processor_type` — type code.
- ℹ️ `cpu_status` — status code.
- ℹ️ `number_of_cores` — cores on that processor.
- ℹ️ `logical_processors` — logical processors on it.
- ℹ️ `address_width` — 64 or 32.
- ℹ️ `current_clock_speed` — current MHz.
- ℹ️ `max_clock_speed` — max MHz.
- ℹ️ `socket_designation` — socket.

`logged_in_users`. One row per session. Stored. Who is logged in now. The first `user` is the fake column above. These fields are the drill-down.

- ℹ️ `user` — the login.
- ℹ️ `tty` — the terminal.
- ℹ️ `host` — where the session came from.
- ℹ️ `time` — when the session started.
- ℹ️ `type` — the kind of session.
- ℹ️ `pid` — the session process.

`interface_addresses`. One row per address. Stored.

- ℹ️ `interface` — the device name.
- ℹ️ `address` — the address.
- ℹ️ `mask` — the netmask.
- ℹ️ `broadcast` — the broadcast address.
- ℹ️ `point_to_point` — the other end, when there is one.
- ℹ️ `type` — the address family.

Not on this list.

- 🔷 Agent fields stay off the machine grid. `connected`, `last_connected`, and `ip` are on `agent`.
- ℹ️ Osquery `users` is the account list. It is not synced. The fake column is the first session, not an account.
- ℹ️ Osquery `uptime` is not synced.
- ℹ️ There is no power-state field.

### Shown

The columns that start visible, in order. The hidden one-row columns are on this same grid and start off.

- ✅ User. The fake column. The first logged-in user.
- ✅ Hostname. `system_info.hostname`.
- ✅ Computer name. `system_info.computer_name`.
- 🔷 A machine shows the one it has. Hostname on a Linux host. Computer name on Windows.
- ✅ Hardware vendor. `system_info.hardware_vendor`.
- ✅ Physical memory. `system_info.physical_memory`.
- ✅ Operating system. `os_version.name` and `os_version.version`.
- ✅ OS status. `os_status`. The OS version is up to date.
- ✅ S/W status. `package_status`. Installed packages are up to date.
- ℹ️ The Agents grid already shows and hides columns from the header. [5.6](5.6-agent-page.md).

### Column file

- 🔷 The grid layout is a CSV. Later grids use the same file.
- 🔷 `columns/machines.csv` is the machine grid. `Base.column_menu` reads it.
- 🔷 The first row is for reading the file. The reader ignores that row.
- 🔷 Pipes and spaces lay those names out. They are not data.
- 🔷 A blank line follows it.
- 🔷 Each later row is the column header, the database name `[JSON]`, `ON` or `off`, the width, and the format.
- 🔷 Database name `[JSON]` is that column as it is serialized. A hyphen stands in for an underscore.
- 🔷 That first line is the approved wording.
- 🔷 The first field is the column header. That text is on the grid.
- 🔷 The first data row is the row header. User. It is drawn bold.
- 🔷 The file order is the column order. The earlier order stays.
- 🔷 A blank line separates a category. Name, hardware, board, memory, CPU, the operating system, then the update pairs.
- 🔷 OS updated sits next to OS status. Package updated sits next to S/W status.
- 🔷 The reader skips an empty line. `shown` is `ON` or `off`. `ON` starts visible.
- 🔷 `text` is a label.
- 🔷 `number` is right aligned.
- 🔷 `date` is a date.
- 🔷 `status` is a circle. On or off for up to date.
- 🔷 `tick` is a tick, a cross, or empty.
- 💩 Which tick pair. Tick and cross, or tick and empty.
- ℹ️ Agents does not use this file yet. [5.6](5.6-agent-page.md).

```
Column header  |  Database name [JSON]  |  ON or off  |  Width in pixels  |  Format

User,user,ON,120,text
Hostname,hostname,ON,180,text

Hardware vendor,hardware-vendor,ON,160,text
Hardware model,hardware-model,off,180,text

OS updated,os-updated,off,140,date
OS status,os-status,ON,120,status

Package updated,package-updated,off,170,date
S/W status,package-status,ON,140,status
```
