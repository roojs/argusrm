# 5.9.1 Assets — Software data collection

## Purpose

- 🔷 How installed software stays in sync. Debian packages, RPM packages, and Windows programs.
- ✔️ The startup snapshot is applied as a differential update.
- 🔷 ⏳ `added`, `updated`, and `deleted` are timestamps on all three tables.
- 🔷 ⏳ The default list leaves deleted rows out. A since time returns rows added, updated, or deleted after that time.
- 🔷 ⏳ The agent installs `osqueryd` with the osquery package and runs it as part of the agent.
- ℹ️ The list is [5.9](5.9-assets-software.md). Filters are [5.9.2](5.9.2-assets-software-filters.md). The machine grid is [5.9.3](5.9.3-assets-software-machines.md). Enrichment is [5.10](5.10-data-enrichment.md).
- ℹ️ Column names are [4.0](4.0-data-types.md).

## Startup snapshot

- 🔷 The agent queries `deb_packages`, `rpm_packages`, and `programs` once at startup and calls `OSQuery.sync`. This host sends about seven thousand Debian rows.
- ℹ️ Android does not query. A database copy after reboot held 7051 `deb_packages` rows for that agent.
- ✔️ The server applies that set as a differential update. `shared/OSQuery/Row.vala` `sync_rows`.
  - A stored row that differs is updated.
  - A new row is inserted.
  - A stored row the snapshot left out is deleted.
  - The table is not wiped and filled again.
- 🔷 ⏳ That apply writes no `added`, `updated`, or `deleted` time.
- 🔷 Those three timestamps go on `deb_packages`, `rpm_packages`, and `programs`.
  - An insert sets `added`.
  - A stored row whose columns change sets `updated`.
  - A row the snapshot left out stays, and `deleted` is set. That replaces the delete `sync_rows` does today.
- 🔷 Each value is a unix time, `INTEGER`. `0` means that has not happened.
- 🔷 A row that comes back after `deleted` clears `deleted` and sets `updated`.
- ℹ️ An install time is kept when osquery already sends one. `rpm_packages.install_time` is a unix time. `programs.install_date` is text. `deb_packages` has no install time. No install column is added. A new package is found by `added`.

## Later updates

Osquery records events in a long-lived process, then a query reads them. [File integrity monitoring](https://osquery.readthedocs.io/en/stable/deployment/file-integrity-monitoring/) and the [pub-sub framework](https://osquery.readthedocs.io/en/stable/development/pubsub-framework/). Checked on osquery 5.24.0.

- 🔷 After the startup snapshot, package changes come from that event feed.
- 🔷 ⏳ The agent installs `osqueryd` and runs it. The same package install that provides `osqueryi`. Linux is the deb or the rpm. Windows is the msi. [2.0](2.0-agent.md).
- 🔷 ⏳ Running it is part of the agent. The agent writes the flag file and the config, starts the daemon, and leaves it running.
- ℹ️ The Linux unit is `osqueryd.service`. It reads `/etc/osquery/osquery.flags` and `/etc/osquery/osquery.conf`. The binary is `/usr/bin/osqueryd`. The agent today looks for `osqueryi` and does not start this unit.
- 🔷 Events are on. `--disable_events=false`. The package watches from the earlier bullets go in that config.
- 🔷 One monitor reads the event tables. A package class, when its event arrives, queries that package table and syncs it.
- 🔷 The server apply is the same differential as startup, so `added`, `updated`, and `deleted` move.
- ℹ️ A one-shot `osqueryi` does not collect events. The buffer is the daemon's RocksDB. A second process cannot open that database. `osqueryi --connect` queries the running daemon.
- ℹ️ Each `*_events` table has `time`. A query should bound it, `time` greater than the last read. `--events_expiry` defaults to a day, and a select drops events older than that. A daemon that was down longer than that loses the buffer. The next startup snapshot covers the gap.
- 🔷 Debian uses `file_events`. The publisher is inotify. The flag is `--enable_file_events=true`. The `file_paths` category watches `/var/lib/dpkg/%`. The directory, because dpkg replaces `status` and a watch on the file itself stops.
- 🔷 RPM uses the same table. The category watches `/var/lib/rpm/%`.
- 🔷 Windows uses `windows_events`. The flags are `--enable_windows_events_publisher` and `--enable_windows_events_subscriber`. The channel is Application. The source is `MsiInstaller`. Install is event `1033` and `11707`. Removal is `1034` and `11724`. That class then syncs `programs`.
- ℹ️ An exe install or a store install does not emit `MsiInstaller`. The startup snapshot still has those programs.
- ℹ️ The event row is the signal. The package row comes from `deb_packages`, `rpm_packages`, or `programs` after that signal.
- 💩 ⏳ How often the monitor reads the buffer is not chosen. The events are already stored. The read is what sends them on.
- ℹ️ The update columns are [5.10](5.10-data-enrichment.md). This section is the installed rows.

## Controller load

- 🔷 The default list leaves out a row whose `deleted` is set.
- 🔷 A later load passes a time. The reply is every row whose `added`, `updated`, or `deleted` is after that time. Deleted rows are in that reply.
- ℹ️ `DebPackages.list`, `RpmPackages.list`, and `Programs.list` take `i`: `agent_id`. There is no since argument. [rpc-commands](../rpc-commands.md).
- ℹ️ The stores still apply a full list with a client hash map. That code stays until this load exists.

## LLM notes

- 🚫 Do not build the Software list here. That is [5.9](5.9-assets-software.md).
- 🚫 Do not build the filters here. That is [5.9.2](5.9.2-assets-software-filters.md).

- 🚫 Do not add `update_available`. That is [5.10](5.10-data-enrichment.md).
- 🚫 Do not add an install-time column. A new package is `added`.
- 🚫 Do not wipe a package table and insert the snapshot again.
- 🚫 Do not drop a row the snapshot left out. Set `deleted`. The since query returns that row.
- 🚫 Do not send a partial package list through `OSQuery.sync`. A row left out of that full set is marked deleted.
- 🚫 Do not watch packages by polling `deb_packages`. The watch is the event table. The package query runs after that event.
- 🚫 Do not send the event row as a package row.
- 🚫 Do not open a second osquery database while `osqueryd` holds it. Query through `--connect`.
- 🚫 Do not leave `osqueryd` for an administrator to start. The agent installs it and runs it.
- 🚫 Do not walk the full lists on the client to find the difference.
- 🚫 Do not extend the client hash-map diff in the stores.
