# 2.6.1 Management client link — specification (agent + controller)

**Status:** ⏳ proposed — **agent `agent/Connection.vala` shape is the target implementation**; **call-site and Application cleanup tracked separately**

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**. [2.6](2.6-management-connection.md). [rpc-commands.md](../rpc-commands.md) (`RPC-Daemon.hello`). **Migration backlog:** [2026-11-19-management-link-application-migration.md](../bugs/2026-11-19-management-link-application-migration.md).

---

## Purpose

- 🔷 Agent and controller each keep **one live TLS session** to the management server while that process is meant to be online.
- 🔷 **`Application` (or `Window`) only does `new` the link** — no `attach_connection`, no “please connect” wrappers.
- 🔷 After that the **link object** owns TLS, hello, reconnect, `watch()`, and forwards server push.
- 🔷 **Monitoring link `state` is for UI information only** — icons, labels, countdowns, enabled chrome.
- 🔷 **Events that start flows** (no certificate, register again, open Bootstrap) are **other signals / existing registration paths** — not “react to every state change with side effects”.
- ℹ️ `Argus.Controller.Connection` is the **saved server row** in `connections.json` — **not** the live TLS link type in this spec.
- ℹ️ Agent **`agent/Connection.vala`** — enum, `enter_state`, six `on_*`, scheduler, inlined config/TLS/hello in handlers; **`client()`** when **`CONNECTED`**. Remaining gaps are in **§ Outstanding (after link shape)**, not a rewrite of the state machine.

---

## Not this object (registration connection)

- 🔷 **Registration** (agent `Shared.Register` / `RegisterWindow`, controller Bootstrap register, Browse) uses a **different, short-lived TLS connection** to argusrm-server. It has its own UI and flow: pick server, registration open/closed, pin sent, waiting for approval, listening, and similar — **not** states on the management **client link**.
- 🔷 While the user is registering, the live link is usually **`absent`** (no `client.pem` / no link constructed). Registration code does **not** drive `link.state`.
- 🔷 Hand-off to this spec’s link only after credentials are written: Application or Window **`new`** the link → **`checking_config`** → **`connecting`** → **`connection_check`** → **`connected`** (or retry/dead).
- 🔷 The live link touches registration only at **hello** on the long-lived session: e.g. cert not registered → **`disconnected_dead`** + `failure_detail`; user opens Register again on the **registration** connection; link may be destroyed → **`absent`** until a new link exists.

---

## Shared principle

- 🔷 One **link object** per process session.
  - Holds the socket privately.
  - **`client()`** is the only way to get a `TlsClient` for outbound RPC.
  - Updates **`state`** and deadline fields in place — **no** link `changed` signal.
- 🔷 **Critical work on the link** — reconnect scheduling, hello, socket `closed`, cert wipe on **disconnected_dead**, `mark_down()` handling. The link does not ask `Application` to drive those steps.
- 🚫 Link does **not** write tray text, Gtk page bodies, or D-Bus status strings.
- 🚫 Link `state` monitoring must **not** trigger registration, inventory, or command dispatch — those use the trees below.

## Implementation shape (enum, state methods, signals)

### Enum and handlers

- 🔷 One **`State` enum** on the link — values match public **`state`** in this spec (`DISCONNECTED_WILL_RETRY`, `CHECKING_CONFIG`, `CONNECTING`, `CONNECTION_CHECK`, `CONNECTED`, `DISCONNECTED_DEAD`). **`absent`** = no object.
- 🔷 **One handler method per enum value** (names match the state, e.g. `on_checking_config`, `on_connecting`, `on_connection_check`, `on_connected`, `on_disconnected_will_retry`, `on_disconnected_dead`). **That method holds the code for “we are in this state now”** — start work, arm deadlines, or idle.
- 🔷 **Entering a state** goes through a single **`enter_state(State s)`** (or equivalent): assign `state`, set related properties (`reconnect_at`, `connect_attempt_until`, `failure_detail`, …), emit property notifies, then **call `on_<s>()`** on the main thread and **return**. Long work is **not** inlined: `on_connecting` / `on_connection_check` start the worker; worker posts back and calls `enter_state(...)` again with the outcome.
- 🔷 **Finishing work** uses small **transition helpers** (`enter_connected`, `schedule_retry`, `enter_dead`, …) that end in **`enter_state`**, not by calling the next `on_*` directly from deep call stacks.

```
enter_state(CHECKING_CONFIG)
└── on_checking_config()
    ├── read server + PEMs on main thread
    └── enter_state(CONNECTING) | enter_state(DISCONNECTED_WILL_RETRY) | enter_state(DISCONNECTED_DEAD)

enter_state(CONNECTING)
└── on_connecting()
    └── worker: TLS dial → enter_state(CONNECTION_CHECK) | schedule retry

enter_state(CONNECTION_CHECK)
└── on_connection_check()
    └── worker: hello + checks → enter_state(CONNECTED) | retry | dead

enter_state(CONNECTED)
└── on_connected()
    └── watch socket; forward server notification; client() live

enter_state(DISCONNECTED_WILL_RETRY)
└── on_disconnected_will_retry()
    └── set reconnect_at; scheduler waits — does not block

enter_state(DISCONNECTED_DEAD)
└── on_disconnected_dead()
    └── clear deadlines; failure_detail already set; idle until destroy / user
```

- 🔷 **Public entry points** only **`enter_state`** (via helpers): `mark_down()` → `enter_state(DISCONNECTED_WILL_RETRY)`; construct → first `enter_state` when scheduler says so.

### Signals (what fires what)

- 🔷 **GObject property notifies** (the main “signals” on the link):
  - **`notify::state`** — UI chrome; **inside the link**, optional if dispatch is only via `enter_state` calling `on_*` directly (still notify for outsiders).
  - **`notify::reconnect_at`**, **`notify::connect_attempt_until`**, **`notify::failure_detail`** — countdown text; **private tick** compares `now` to deadlines and may `enter_state(CHECKING_CONFIG)` when `reconnect_at` due or abort attempt when cap exceeded.
- 🔷 **Internal edges** (not for Application to wire):
  - **scheduler tick** — `disconnected_will_retry` + deadline → `enter_state(CHECKING_CONFIG)`; cap exceeded in `connecting` / `connection_check`.
  - **worker Idle callback** — result → `enter_state(...)`.
  - **`TlsClient.closed`** — `enter_state(DISCONNECTED_WILL_RETRY)` (or schedule).
- 🔷 **Server push** — `TlsClient.notification` on the open socket → forward to `Application.notification` / `Window` (same as today). **Not** link `state`.
- 🔷 **Registration UI** — Register window signals, tray actions, Bootstrap — **separate objects**; not link enum handlers.

```
Application / Window
├── new link when certs + server exist
├── notify::state / deadlines on link → repaint tray or header only
├── Application.notification ← socket notification when CONNECTED
└── 🚫 do not call enter_state or attach_connect from Application

Link (private)
├── enter_state → on_<state>()
├── property notifies → UI + optional internal tick
└── socket closed / worker done → enter_state
```

- 🚫 Custom link **`changed`** / **`publish()`** — dropped; use enum + properties + **`notify::*`** only.
- ⏳ Today’s draft: wrong enum names, `attach()` from outside, `publish()` — replace on implementation.

### Do we need custom link signals?

- ℹ️ In Vala/GObject, **`notify::state` is already a signal** — GObject emits it when the **`state`** property changes. Same for **`notify::reconnect_at`**, **`notify::connect_attempt_until`**, **`notify::failure_detail`**. No extra “state changed” signal is required for outsiders to listen.
- 🔷 **Custom link signal** = you declare e.g. `signal void changed()` and **`emit`** it yourself. That duplicates what **`notify::state`** already tells listeners (“state property changed”). **💩 Default: no custom signals on the link** — only GObject properties + their **`notify::*`**.
- 🔷 **`notify::state`** vs **`on_connecting()`**:
  - **`enter_state`** sets the property and calls **`on_<state>()`** **directly** — the state machine does **not** depend on wiring **`notify::state`** to handlers inside the same object.
  - **Outside** (tray, Gtk, Window) may connect **`notify::state`** to **redraw** when the enum changes; they still **poll or tick** for “N seconds left” using **`reconnect_at` / `connect_attempt_until`** without a notify every second.
- 🔷 **`notify::state`** fires only when the **enum value changes** (e.g. `connecting` → `connection_check`). It does **not** fire each tick of a countdown. When a **deadline property** is set or cleared, **`notify::reconnect_at`** / **`notify::connect_attempt_until`** fires once.
- 🔷 **Other signals** in the system are **different objects**: **`TlsClient.closed`**, **`TlsClient.notification`** (server push), Register window / tray — not replacements for link **`state`**.

```
Need custom link "changed" signal?
└── No — use state + failure_detail + deadlines as properties; listeners use notify::*

Who advances the machine?
└── enter_state → on_*() inside the link (not Application on notify::state)

Who paints "try again in 5"?
└── UI tick reads reconnect_at; optional notify when deadline is (re)set
```

## State machine (in depth)

- 🔷 State **`disconnected_will_retry`** — not connected now; **retry scheduled** — link sets `reconnect_at` (when the next attempt starts at **`checking_config`**).
- 🔷 State **`disconnected_dead`** — not connected; **no retry schedule** until destroy, new link, or user action (`failure_detail` set).
- 🔷 **Every step below sets `state`** (and usually `reconnect_at`, `connect_attempt_until`, or `failure_detail`).
- 🔷 ***Triggers*** in the trees = what **other layers MAY do** when the link is in that state — **not** GObject signals that advance the link. The link advances itself via its **private scheduler** after transition methods set properties.
- 🚫 Do not start inventory, registration UI, or tab loads from a generic state listener — only the *Triggers* listed for that state.
- 💩 Agent reconnect delay **5 s** / open cap **8 s**; controller **30 s** in `Window` today — one policy on approval.
- 🔷 State **`checking_config`** — read stored **server** address and **load** client cert, key, CA from disk or secret store (`client()` null). UI may show nothing or a brief “Preparing…” — **not** “Connecting…”.
- 🔷 State **`connecting`** — **TLS dial** to argusrm-server in progress (`client()` null). UI label “Connecting…”. **Does not** read disk (**`checking_config`**) or run hello (**`connection_check`**).
- 🔷 State **`connection_check`** — TLS socket is up; link runs **checks on that connection**: `RPC-Daemon.hello`, version compare, policy/errors (`client()` still null until **`connected`**). UI may stay “Connecting…” (same countdown) or “Verifying…”.
- 🔷 **Tls** and **hello** run off the UI thread. **Not** registration UI, **not** disk load.
- 🔷 A full attempt is **`checking_config` → `connecting` → `connection_check`** (or stop early). **`connect_attempt_until`** covers **`connecting` + `connection_check`**. Ends in **`connected`**, **`disconnected_will_retry`**, or **`disconnected_dead`**.

### States (catalog)

```
absent
├── no link object in the process (agent: no client.pem yet; controller: Bootstrap, no server picked)
├── client() N/A
└── no link deadlines

disconnected_will_retry
├── retry scheduled via reconnect_at (monotonic deadline)
├── session down until then; client() null
├── when now ≥ reconnect_at → checking_config (re-read same stored material)
└── 🚫 not absent; not disconnected_dead

checking_config
├── read host:port; load client cert, key, CA; validate present (main thread)
├── client() null
├── config OK → connecting (same attempt)
└── config bad → disconnected_will_retry or disconnected_dead (see transitions)

connecting
├── TLS dial only (worker); in-memory material from checking_config
├── client() null
├── TLS OK → connection_check (same attempt; connect_attempt_until still running)
└── TCP/TLS fail or cap exceeded → disconnected_will_retry

connection_check
├── hello + version/policy checks on the open TLS socket (worker)
├── client() null until checks pass and state becomes connected
├── same connect_attempt_until as connecting; cap exceeded → disconnected_will_retry
└── exit: connected | disconnected_will_retry | disconnected_dead

connected
├── socket watched; notifications forwarded
├── client() returns socket
└── no retry/connect deadlines while up (socket watch only)

disconnected_dead
├── reconnect_at / connect_attempt_until cleared (not meaningful until user or new link)
├── client() null
└── failure_detail explains why (not registered, version, policy, missing cert, …)
```

### Transitions (event → next state → link actions)

```
Construct
├── agent: client.pem missing → absent
│   └── triggers: registration layer may show register UI (see absent)
├── agent: client.pem present → disconnected_will_retry or checking_config (immediate first try)
│   └── link: set reconnect_at if starting in disconnected_will_retry
└── controller: user picked server in Bootstrap → disconnected_will_retry or checking_config
    └── link: bind server name + secrets for this link instance

checking_config
├── server address missing or bad
│   ├── next: disconnected_will_retry
│   ├── link: schedule reconnect_at; clear failure_detail; retry yes
│   └── triggers: UI try-again countdown when back in disconnected_will_retry
├── cert, key, or CA missing
│   ├── next: disconnected_dead
│   ├── link: set failure_detail (no certificate); clear retry/connect deadlines
│   └── triggers: UI show detail; user may open **registration** (separate connection)
└── config OK
    ├── next: connecting
    └── link: set connect_attempt_until; start worker for TLS dial

connecting (TLS dial only)
├── connect_attempt_until exceeded
│   ├── next: disconnected_will_retry
│   └── link: abandon attempt; schedule reconnect_at
├── TCP or TLS fails or times out
│   ├── next: disconnected_will_retry
│   ├── link: schedule reconnect_at; retry yes
│   └── triggers: UI countdown from connect_attempt_until
└── TLS OK
    ├── next: connection_check
    └── link: same worker continues with hello on this socket

connection_check (checks on open TLS)
├── connect_attempt_until exceeded
│   ├── next: disconnected_will_retry
│   └── link: close socket; abandon attempt; schedule reconnect_at
├── no RPC reply / transport error (retryable)
│   ├── next: disconnected_will_retry
│   ├── link: schedule reconnect_at; retry yes
│   └── triggers: UI countdown
├── hello CERT_NOT_REGISTERED
│   ├── next: disconnected_dead
│   ├── link: wipe agent cert files; failure_detail; clear retry/connect deadlines
│   └── triggers: UI + user re-register; after Register → absent then new link → checking_config
├── hello other RPC error (permanent)
│   ├── next: disconnected_dead
│   ├── link: failure_detail = server message; retry no
│   └── triggers: UI; registration only if user decides
├── client version newer than server
│   ├── next: disconnected_dead
│   ├── link: failure_detail = version mismatch; retry no
│   └── triggers: UI (upgrade server or downgrade client)
├── client version older than server
│   ├── next: connected (after log warning)
│   └── link: proceed as hello OK
└── hello OK
    ├── next: connected
    ├── link: watch(); clear failure_detail; attach notification forward
    └── triggers: see connected

connected
├── socket closed callback
│   ├── next: disconnected_will_retry
│   ├── link: drop socket; reconnect_at soon (immediate or retry delay)
│   └── triggers: UI disconnected chrome
├── mark_down() from RPC consumer
│   ├── next: disconnected_will_retry
│   └── link: same as socket closed
└── (stays connected otherwise)

disconnected_will_retry
├── reconnect_at reached
│   └── next: checking_config
└── (stays disconnected_will_retry until then)

disconnected_dead · user / lifecycle
├── user or controller disconnect destroys link
│   └── next: absent or teardown (controller → Bootstrap)
├── agent: Register completes with new certs
│   └── next: new link object → checking_config (old link destroyed)
└── 💩 user “retry” from UI without register
    └── next: disconnected_will_retry or checking_config — confirm on approval
```

### Triggers by state (what else may do — not automatic from link)

```
absent
├── registration layer MAY: Browse, Register, Bootstrap pick server, tray register
├── UI MAY: show not registered / choose server
└── MUST NOT: construct link without new certs or server choice

disconnected_will_retry
├── UI MAY: show try again countdown from reconnect_at
├── registration layer: idle
└── MUST NOT: client() consumers expect null

checking_config
├── UI MAY: brief preparing chrome or skip (fast)
├── registration layer: idle
└── MUST NOT: treat as connected; client() null

connecting
├── UI MAY: show “Connecting…” countdown from connect_attempt_until
├── registration layer: idle — **not** registration open/listening (that is Register’s connection)
└── MUST NOT: inventory, agent.run handling (not connected yet)

connection_check
├── UI MAY: same countdown or “Verifying…” (connect_attempt_until still applies)
├── registration layer: idle
└── MUST NOT: client() for RPC yet (not connected until hello OK)

connected
├── monitors MAY: client() for RPC to argusrm-server
├── process handler MAY: run server notifications
├── UI MAY: show connected
├── 💩 Application MAY: one-shot inventory start (agent Windows) — explicit hook, not notify::state
└── registration layer: idle

disconnected_dead
├── UI MAY: show failure_detail; offer register / configure / disconnect
├── registration layer MAY: user starts Register or Bootstrap register (not link calling it)
├── user MAY: destroy link and return to absent
└── MUST NOT: silent auto-open registration without user (unless promoted 🔷 later)
```

### Three “not connected” situations

```
absent
└── no link object — need register or pick server first

disconnected_will_retry
└── link exists; certs present; **will retry** argusrm-server at reconnect_at

disconnected_dead
└── **dead** — no auto-retry; failure_detail; user or **registration connection** must fix
```

### Registration vs reconnect (do not mix up)

```
Need a certificate or server choice
├── client.pem missing at agent start → absent (no link object)
├── user on Bootstrap picking a server → absent until Window constructs link
└── hello says not registered → disconnected_dead → user runs Register → absent → new link

Already have cert + address; session just failed
├── TCP/TLS/timeout / retryable hello → disconnected_will_retry (try same server again later)
├── socket dropped while running → disconnected_will_retry (often immediate reconnect_at)
└── registration layer idle while state is disconnected_will_retry
```

### Process-level note

- ℹ️ **absent** is not a `state` on the GObject — no object. Agent UI treats “no client.pem” as absent before `new`.
- 🔷 Public **`state`**: `disconnected_will_retry`, `checking_config`, `connecting`, `connection_check`, `connected`, `disconnected_dead`. **`absent`** = no link object (not on the enum).

## Properties and countdowns (not a link “timer signal”)

- 🔷 `state`
- 🔷 `failure_detail` — server/policy when not retrying; empty while retrying
- 🔷 `reconnect_at` — monotonic µs deadline; meaningful in **`disconnected_will_retry`** (“try again at …”)
- 🔷 `connect_attempt_until` — monotonic µs deadline; meaningful in **`connecting`** and **`connection_check`** (one cap for the whole dial + hello attempt)
- 🔷 `is_up()` — same as `client() != null`
- 🔷 The link **does not** emit a once-per-second signal with “N seconds left”. It **sets deadline properties** when scheduling retry or starting an attempt. UI computes **N** = `(deadline − now)` on its **existing** tick (tray poll, Gtk timer, Win32 `agent.status`).
- 🔷 When a deadline is (re)set, normal GObject **`notify::reconnect_at`** / **`notify::connect_attempt_until`** / **`notify::state`** — that is the **event with a number** (absolute µs), not a custom link `changed` signal.
- 🚫 Custom link **`changed`** or repeating **`tick`** signals — countdown is local to UI/service formatting.

## How the live link fits (trees)

- ℹ️ **Live link** = GObject for TLS + reconnect (name TBD). Not `Argus.Controller.Connection` (JSON row).
- ℹ️ **Remote peer** = **argusrm-server** TLS listener at `host:port` (agent: `data_dir/server`; controller: saved row + probe).

```
Both programs
├── Live link object (local)
│   ├── loads client cert + CA from disk or secret store
│   ├── opens TLS socket to argusrm-server at stored host:port
│   ├── sends RPC-Daemon.hello; checks server version in the reply
│   ├── calls watch() on the socket for inbound server notifications
│   ├── forwards each notification to the process handler (agent or window)
│   ├── closes and re-opens the socket when it drops or after mark_down()
│   ├── sets state + deadline properties while disconnected_will_retry, disconnected_dead, checking_config, connecting, or connection_check
│   └── returns the open socket from client() for outbound RPC calls
├── argusrm-server (remote)
│   ├── terminates TLS; verifies the agent or controller client cert
│   ├── handles hello; returns its version string
│   ├── accepts RPC calls on the same connection (inventory, Agent.list, …)
│   └── emits notifications (agent.run, …) on that connection
├── Application or Window (local)
│   └── constructs the live link when this process should stay connected to one server
├── Registration or Bootstrap (local; not the link)
│   ├── writes certs and host:port to disk or secret store
│   ├── then tells Application or Window to construct a new live link
│   └── opens registration UI when certs are missing (user action; not link state)
└── UI chrome (local)
    ├── reads link.state and deadlines to paint status (tray, Gtk, window header)
    └── does not open TLS or call hello
```

```
Agent
├── Shared.Register (+ Browse when needed)
│   ├── dials argusrm-server for registration (separate short flow)
│   ├── writes client.pem, server, CA into Application.data_dir
│   └── ends; Application then constructs the live link
├── Application
│   ├── constructs live link when client.pem exists
│   └── handles Application.notification for commands the server pushes
├── Live link
│   ├── reads host:port from data_dir/server on each open attempt
│   ├── opens long-lived TLS to argusrm-server; hello as argus-agent
│   └── forwards socket notifications to Application.notification
├── Win32.Service
│   ├── polls link.state + deadlines for agent.status RPC replies
│   └── broadcasts status to Tray (Service formats strings)
├── linux Application (Gtk)
│   └── answers D-Bus ServiceStatus from link.state (+ registration files)
└── OSQuery, PackageMonitor, UserMonitor, Command, Rdp
    ├── call link.client() to send RPC to argusrm-server
    └── call link.mark_down() when a send fails
```

```
Controller
├── Dialog.Bootstrap
│   ├── loads connections.json rows (Controller.Connection)
│   ├── loads TLS material from secret store per server name
│   ├── may open a short TLS call to argusrm-server to see which saved server answers
│   └── opens Window when the user picks a server
├── Window
│   ├── constructs live link for that server name
│   ├── reads link.state for window chrome (formats strings locally)
│   ├── handles notifications forwarded from the link (lists, tasks, …)
│   └── on user disconnect, destroys link and shows Bootstrap again
├── Live link
│   ├── loads host:port from the chosen row + secrets from the store
│   ├── opens long-lived TLS to argusrm-server; hello as argus-controller
│   └── forwards socket notifications to Window dispatch
└── Agents store, tabs, tasks, …
    └── call link.client() to query or change data on argusrm-server
```

## Event sources tree (link notify + other objects)

- ℹ️ **“Signals”** here means **who emits what** — mostly **`notify::*` on link properties**, not custom link signals. See **Do we need custom link signals?** above.
- 🔷 **Recommendation:** **`notify::state`** on the link → **change UI information only**. Business flows → **registration paths** and **server `notification`**, not Application reacting to every state change.

```
Process
├── Live link object
│   ├── sets state + failure_detail + reconnect_at + connect_attempt_until
│   │   └── UI reads them on a timer or hooks notify::state (chrome only)
│   ├── exposes client() so callers send RPC on the open socket
│   └── accepts mark_down() when a caller’s RPC send fails
│
├── argusrm-server pushes on the open socket (inbound)
│   └── link forwards TlsClient.notification to:
│       ├── Agent → Application.notification runs agent.run, agent.send, relay.*, …
│       └── Controller → Window runs list refresh, command dispatch, …
│
├── Registration and credentials (separate flows)
│   ├── User or tray opens register when client.pem missing
│   ├── Register / Bootstrap writes certs then Application or Window constructs link
│   ├── Link enters disconnected_dead; sets failure_detail when hello returns not registered
│   │   └── UI shows detail; user may register again (not automatic on notify::state)
│   └── 💩 auto-open register on disconnected_dead — confirm on approval
│
└── Do not wire these to notify::state
    ├── start agent inventory (Windows)
    ├── load controller main tabs
    └── open registration — explicit user or cert-missing checks only
```

- 🚫 Custom link **`changed`** signal.

## Agent

- 🔷 Create link: `application.server = new Connection(application)` in ctor when the process should own a link; **not** `attach_connection` long term.
- 🔷 **UI:** `Win32.Service` / tray / GtkDBus status — read `server.state`, deadlines, `failure_detail`; **`notify::state`** for chrome only.
- 🔷 **Inventory:** 💩 prefer explicit hook once **connected** (registration complete path or one guarded `notify::state` handler in `Application`) — **not** inside the link class. Today Windows inventory starts from `Connection.enter_connected`; Linux still polls in `Application.command_line`.
- 🔷 **One-off TLS** (Gtk CLI hello without watch) — exception path; spec § Outstanding; not the long-lived link.
- ⏳ **`Application` + call sites** — see **§ Outstanding (after link shape)** and [migration bug](../bugs/2026-11-19-management-link-application-migration.md).

## Controller

- 🔷 Create link when `Window` opens for chosen server; link stays up while `running_window`.
- 🔷 **Bootstrap** may probe saved servers — short-lived opens; **separate** from the long-lived window link.
- 🔷 **UI:** `Window` / tabs read link properties; server **`notification`** for live data.
- 🔷 **Disconnect** user action tears down link, returns to Bootstrap — UI-driven.
- ⏳ Today: reconnect in `controller/Window.vala`, `Application.rpc` — mess to replace.
- 💩 CLI / Android ephemeral connect — share link type or stay separate; confirm on approval.
