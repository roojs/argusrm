## Phase 1.1 — RPCs

`⏳` Controller calls on the Unix socket. A TLS connection may call them when that row's `is_controller` is set. Same rule as `Command.run`.

Reply `retval` is the row, or an array of rows, unless a call says otherwise. Wire objects are the shared table types.

### ScriptRepository

- **Clone a repository** (`ScriptRepository.clone`) — URL, optional alias, username and password or a key. `✔️`
  - Arguments `o`: that `script_repository` row.
  - `Ggit.Repository.clone` into `git/{name}`. Empty name uses the last part of the URL.
  - Clone first. The row is inserted only after that succeeds. Fills `script` from the tree.
  - Reply: the row.
- **Pull a repository** (`ScriptRepository.pull`) — fetch, then refresh `script` rows. `✔️`
  - Arguments `i`: `script_repository.id`.
  - Uses the stored username and password, or the key.
  - Reply `o`: those `script` rows.
- **Remove a repository** (`ScriptRepository.remove`) — delete a clone. `✔️`
  - Arguments `i`: `script_repository.id`.
  - Removes `git/{name}`, its `script` rows, and this row.
- **List repositories** (`ScriptRepository.list`) — the clones. Not `scripts/`. `✔️`
  - Arguments: none.
  - Reply `o`: the rows.

---

### Script

- **Create a script** (`Script.create`) — a new file under `scripts/`. Not on a clone. `✔️`
  - Arguments `ss`: path, body.
  - Writes the file and commits. `script_repository_id` is 0.
  - Reply: the `script` row.
- **Update a script** (`Script.update`) — save from the editor. Commits. `✔️`
  - Arguments `is`: `script.id`, body.
  - Only a file under `scripts/`.
  - Reply: the `script` row.
- **Read a script** (`Script.read`) `✔️`
  - Arguments `i`: `script.id`.
  - Reply `s`: the file body.
- **List scripts** (`Script.list`) `✔️`
  - Arguments `i`: `script_repository.id`. `0` is the files under `scripts/`.
  - Reply `o`: the rows.
- **Enable a script on a machine** (`Script.enable`) — writes `script_agent`. `Agent.list` already exists. `✔️`
  - Arguments `ii`: `script.id`, `agent.id`.
  - Reply: the `script_agent` row.
- **Disable a script on a machine** (`Script.disable`) `✔️`
  - Arguments `ii`: `script.id`, `agent.id`.
- **List machines a script may run on** (`Script.agents`) — the pick list. `✔️`
  - Arguments `i`: `script.id`.
  - Reply `o`: the `script_agent` rows.

---

### Task

- **Create a task** (`Task.create`) — optional name. Script or command. Template or not. No targets yet. `✔️`
  - Arguments `o`: the `task` row.
  - A template forces `scheduled` negative.
  - Reply: the row.
- **Update a task** (`Task.update`) — replace editable task properties. `✔️`
  - Arguments `o`: the `task` row with its id.
  - Updates name, script or command, template flag, and schedule.
  - Preserves id, `is_draft`, and completed.
  - Rejects an update after approval or completion.
  - Approval freezes both the task definition and its target set.
  - Re-arms the scheduler after a schedule change.
  - Reply: the row.
- **List tasks** (`Task.list`) `✔️`
  - Arguments: none.
  - Reply `o`: the rows.
- **Add targets** (`Task.target`) — selected machines on a draft task. `✔️`
  - Arguments `iv`: `task.id`, an `ai` variant of `agent.id` values.
  - Each agent must already be in `script_agent` for this `script_id`.
  - Rejects target changes after approval or completion.
  - The controller works out whether that is every enabled machine or a subset.
  - Reply `o`: the `task_target` rows.
- **Set task approval** (`Task.approve`) — approve or return to draft. `✔️`
  - Arguments `ib`: `task.id`, then approved.
  - Approved `1` clears `task.is_draft`; `0` sets it.
  - Either toggle is accepted only before the scheduled time.
  - Approval requires at least one target.
  - Re-arms the server scheduler for this task when necessary.
- **Cancel a task** — stop work after the task has started. `⏳`
  - This is separate from the pre-schedule approval toggle.
  - Stop every running command belonging to the task.
  - Prevent its queued targets from starting.
  - Remove the task from scheduler work immediately.
  - Mark affected targets cancelled without deleting execution history.
  - Settle command-kill acknowledgement, target end state, and RPC arguments
    before implementation.
- **Duplicate a task** (`Task.duplicate`) — copy for a later update. `✔️`
  - Arguments `i`: source `task.id`.
  - Copies task properties as a draft and resets completed.
  - Copies targets and clears execution state.
  - Use `Task.update` to change the template flag or schedule on the copy.
  - Reply: the new row.
- **List targets** (`Task.targets`) `✔️`
  - Arguments `i`: `task.id`.
  - Reply `o`: the `task_target` rows.
- ℹ️ There is no normal-flow target delete RPC. A target that has started is retained as execution history.
- 🔷 `⏳` Add retention pruning later as a separate maintenance process, with its own age/policy boundary.

## Phase 1.5 — schedule

- 🔷 `✔️` `Scheduler` has one main-context timeout for the earliest future schedule.
- 🔷 `✔️` Each target has its own delay time, default 0. Its effective run
  time is the greater of that value and `task.scheduled`.
- 🔷 `✔️` Startup dispatches target schedules already due, then arms that timeout.
- 🔷 `✔️` Updating, approving, or duplicating a scheduled task cancels and recalculates the timeout.
- 🔷 `✔️` Database, scheduling, and socket work stay on the main context. No scheduler thread polls while idle.
- 🔷 `✔️` `Task.run` is the scheduler entry point and walks ready targets.
- 💩 Command dispatch from `Task.run` is currently a placeholder. Ready targets are logged but not marked started.
- 🔷 `⏳` Each ready target on an approved task will run through the existing command flow.
- 🔷 Targets on a draft task are not run.
- 🔷 A machine that already has a started target with no `ended` does not start another.
- 🔷 `✔️` A due target whose machine is busy is rescheduled for 60 seconds
  later without delaying due targets on other machines.
- 🔷 `⏳` The first `Command.run` for a target writes `started` and `identifier`.
- 🔷 `⏳` `Command.ended` writes `ended` and the exit code on `success`.
- 🔷 `⏳` When the last target ends, write `task.completed`.
- ℹ️ Output stays in the command log tree. Do not put it in the row.
- ℹ️ `controller.stdout` / `stderr` / `ended` stay as they are. The run is not a new call.
- 💩 A one-line command with no `script_id`. Enablement is still open in [7.0](7.0-tasks.md).
